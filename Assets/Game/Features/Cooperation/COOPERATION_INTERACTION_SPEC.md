# 03 협동·상호작용 구현 명세

상태: 구현 명세 초안
담당: Cooperation, Interaction, Items, Puzzles
범위: 2~4인 1인칭 3D 협동게임의 협동 행동·대상 선택·아이템·퍼즐 상태

## 기준과 구분

- 확정 기획: 2~4인 협동, 직접 공격 없음, 서버 최종 판정, 구간 시작 인원 기준 협동 역할.
- 프로토타입 승인 규칙: 친구 점프, 운반·밀기, 지역 협동 장치, 구조 입력, 보스 시험 규칙.
- 미정: 힐러 시간, 부활 체력·보호·패널티, 아이템 슬롯·공유 범위, 협동 도구·증강 도입 시점, 최종 UI·연출.
- 문서에 정의된 규칙과 현재 코드의 존재는 정상 게임 동작·PlayFab 연결 완료를 뜻하지 않음.

## 책임 경계

| 영역 | 소유 책임 |
|---|---|
| Cooperation | 구조·끌어올리기·친구 점프·상호 지탱·협동 조건 |
| Interaction | 조준·근접 후보·우선순위·입력 요청 전달 |
| Items | 정의·획득·소유·소모·전달·필수 아이템 복구 |
| Puzzles | 문·스위치·동시 장치·정화·역할 요구·성공/실패 상태 |
| Player | 이동·체력·다운·사망·부활·점유 가능성 |
| Online | 인증·요청 권한·동기화·중복 요청 방지 |
| StartandExit | 구간 전환 부활·전멸·출구 개방 결과 연결 |

기본 흐름은 `입력 → 대상 선택 → 기능별 요청 → 서버 검증 → 상태 확정 → 동기화 → 표시`로 유지함. UI나 다른 기능이 내부 상태를 직접 덮어쓰지 않음.

## Cooperation

### 친구 점프

1. Interaction이 앉아 있는 생존 팀원을 후보로 선택함.
2. 서버가 양쪽 참가자 연결 상태·행동 가능 상태·거리·상대 위치를 검증함.
3. 서버가 점프 보조 결과를 확정하고 Player 이동 연결부에 전달함.
4. 대상 이동·사망·거리 이탈·연결 종료 시 요청을 취소함.

기본 점프의 2.5배는 시험값으로만 취급하며 최종 수치로 고정하지 않음.

### 끌어올리기

- 위쪽 플레이어가 근처의 생존 팀원을 조준하고 상호작용 입력을 누름.
- 서버가 양쪽 상태, 거리, 상대 높이, 목적지 점유 가능성을 재검증함.
- 성공 시 기존 Player 이동 기능을 호출함.
- 목적지 충돌·공간 부족·대상 상태 변경 시 이동하지 않고 취소함.
- 클라이언트의 임의 Teleport를 성공 판정으로 사용하지 않음.

### 구조·부활

상태: `None → Targeted → Holding → Revived`.

- 다운된 팀원을 조준함.
- 회복팩 또는 힐러 특기를 서버가 확인함.
- 기본 구조 입력은 Interact 유지 방식임. 기존 3초는 프로토타입 값임.
- 입력 해제·거리 이탈·대상 상태 변경·구조자 사망/이탈 시 진행을 초기화함.
- 성공 시 Player 부활 결과와 Items 소모를 한 번만 확정함.
- 힐러 추가 시간, 부활 체력·보호 시간·패널티는 미정으로 유지함.

### 공동 밀기와 지탱

- 대형 물체의 플레이어별 방향 요청을 서버가 수집함.
- 같은 방향의 유효 힘은 합산하고 반대 방향의 힘은 상쇄함.
- 요청 시각·참가자 ID·연결 상태를 검증함.
- Chapter06 상호 지탱은 양쪽 플레이어가 서로 유효한 지원 대상으로 유지될 때만 성립함.
- 한쪽 입력 해제·거리 이탈·행동 불가 시 지원 상태를 취소함.

## Interaction

후보 검색 순서:

1. 구조·끌어올리기 대상
2. 상호 지탱 대상
3. 조준 중 장치·아이템
4. 상자·물리 물체

후보는 거리·시야 차단·접근 가능성·연결 상태·행동 가능 상태·출구 대기 상태를 확인함. 참가자 목록의 첫 일치 결과에 의존하지 말고 조준각·거리·안정적인 대상 ID로 결정적인 선택을 보장함.

입력은 `Pressed`, `Held`, `Released`, `Cancel`로 구분함. 클라이언트 Prompt와 진행률은 성공 판정이 아니며, 서버가 대상·거리·소유권·현재 상태를 다시 검사함.

상호작용 요청은 재전송 가능한 requestId와 처리 결과를 연결해야 함. 현재 프로토타입의 매 호출 새 GUID 방식은 최종 네트워크 중복 방지 계약으로 사용하지 않음.

## Items

생명주기: `World → Acquire → Owned → Use/Transfer/Drop → Consumed 또는 World`.

- 회복팩: 회복·구조에 사용하는 소모품.
- 열쇠: 현재 프로토타입은 재사용 도구이나 최종 소모 여부는 미정.
- 유인구: 사용 시 유인 오브젝트를 만들며 만료·구간 전환 정리는 서버 상태와 연결함.
- 로프 등 이동 보조 도구: Player 이동 기능과 연결하되 최종 효과는 미정.
- 획득·소모·전달은 서버 원자 처리로 중복 적용을 막음.
- 아이템 슬롯 수, 바닥 전달, 공유 가방 범위는 설정 가능한 구조로 유지함.
- 상점·제작·조합은 추가하지 않음.
- 중요 퍼즐 아이템은 분실·낙하 시 지정 복구 위치로 되돌림.

## Puzzles

일반 상태: `Locked → Available → Holding/Progress → Completed`.

- 입력 해제·거리 이탈·참여자 행동 불가 시 유지 조건을 해제함.
- 누적 완료 조건 보존 여부는 장치 규칙으로 명시함.
- 전멸 초기화는 StartandExit 요청으로 연결하고 Puzzles가 런 전체를 직접 초기화하지 않음.
- 구간 시작 참가자 수를 `RequiredRoles`로 저장함.
- 사망·이탈로 `RequiredRoles`를 줄이지 않음.
- 역할 부족 시 자동 완화·순차 대체·재시작 버튼을 추가하지 않음.
- 주변에 실제 전멸 가능한 경로가 있어야 하며 배치 검사는 Levels/MapGeneration이 담당함.

현재 프로토타입 지역 규칙은 다음과 같음.

- Chapter01: 장치 유지 + 다른 플레이어 화물 운반.
- Chapter02: 서로 다른 두 플레이어의 장치 유지.
- Chapter03: 장치 유지 + 필터 화물 운반.
- Chapter05: 한 명 유지 + 다른 플레이어 순서 입력.
- Chapter07: 유지·화물·순서 입력 결합.
- 보스: 협동 장치 충전과 공격 예고.

지역 수치와 최종 퍼즐 조합은 미정임.

## 예외 처리

- 대상 파괴·비활성화: 진행 상태와 예약 참조를 즉시 정리함.
- 입력 해제·거리 이탈: 유지형 행동을 취소함.
- 사망·다운·출구 대기: 신규 협동 요청을 거부함.
- 연결 종료·씬 전환: 소유권·임시 진행·이벤트를 정리함.
- 중복·지연·역순 요청: requestId와 현재 상태를 대조해 재적용하지 않음.
- 아이템 슬롯 부족: 획득·전달을 모두 거부하고 기존 소유 상태를 보존함.
- 물체 회수 불가: Essential 및 퍼즐 필수 아이템 복구 규칙을 적용함.

## 다른 담당 채팅 요구사항

- 01 Core: 공통 요청 ID·시간·결과 형식만 제공.
- 02 Player: 행동 가능·다운·부활·보호·점유 가능성·협동 이동 연결부 제공.
- 04 StartandExit: 구간 전환 부활과 전멸 초기화 이벤트 제공.
- 05 Monster/MapGeneration: 중요 아이템 복구 위치와 협동 필수 구간의 접근 가능한 사망 경로 제공.
- 07 Online: 발신자·소유권·requestId 검증 및 협동/아이템/퍼즐 상태 복제 제공.
- 08 UI: 행동 ID·대상명·진행률 표시만 연결하며 최종 스타일은 사용자 승인 후 결정.
- 09 Testing/Maintenance: 이 명세를 기준으로 별도 작업 기록과 실제 검증 기록 작성.

## 구현 순서

1. 기존 Player·Online 상태 계약 확인.
2. Interaction 후보 선택과 입력 상태 분리.
3. Cooperation 협동 조건·구조 상태 소유권 분리.
4. Items 획득·소모·전달 원자성 연결.
5. Puzzles 역할 스냅샷·장치 상태·초기화 경계 연결.
6. 외부 담당 변경 요구사항 전달 후 통합.
