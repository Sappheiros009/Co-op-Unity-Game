# Puzzles — 퍼즐과 장치

## 다음 작업자용 빠른 안내

- 쉬운 이름: 장치 성공 조건.
- 수정 시작점: [PrototypeStageObjective.cs](PrototypeStageObjective.cs).
- 현재 담당: 협동 역할·장치 조건·현재 프로토타입 보스 기믹.
- 이 폴더만으로 처리하지 않는 범위: 조준 입력·영구 저장.
- 함께 확인: Interaction, MapGeneration, Online.
- 지시 예시: “장치를 켜도 문이 안 열림 → Features/Puzzles → PrototypeStageObjective.cs → Interaction, MapGeneration, Online와 영향 확인”.
- 아래 상세 기획은 목표 책임, 날짜가 있는 구현·검사 기록은 해당 시점의 이력이다. 코드 존재와 정상 동작·서비스 연결 완료를 구분한다.

## 담당 범위

- 문·스위치·동시 조작 장치·정화 장치의 작동 조건과 상태를 담당합니다.
- 용암·전기 같은 환경을 이용한 장치와 적 처리 규칙을 연결합니다. 실제 배치와 지역별 수치는 Levels에서 관리합니다.

## 협동 필수와 혼자 수행 가능한 구간

[출구와 팀 점수 설계](../../../../Docs/DESIGN-0001-StageExit.md)의 확정 규칙을 따릅니다.

- 여러 명의 동시 역할이 반드시 필요한 구간과, 혼자서도 수행할 수 있지만 시간이 오래 걸리는 구간이 함께 존재합니다.
- 협동 필수 조건이 남아 있는데 역할 인원이 부족하면 혼자 통과할 수 없고 재도전해야 합니다. 모든 장치를 생존 인원에 맞춰 자동 완화하거나 순차 처리로 바꾸지 않습니다.
- 출구 개방 조건과 StartandExit의 한 명 진입 클리어 조건은 별개입니다. 여러 명이 출구를 열어 놓고 일부만 탈출하는 방식도 두 조건을 분리하면 설명할 수 있습니다.
- 이미 충족한 조건, 현재 필요한 역할, 현장 구조 가능성을 확인한 뒤 진행 불가 여부를 검토합니다. 죽은 사람이 있다는 이유만으로 모든 장치를 초기화하는 규칙은 추가하지 않았습니다.
- 협동 필수 역할은 구간 시작 참가 인원에 맞춰 구성하고 진행 중 사망으로 줄이지 않습니다. 구체적인 역할·장치·배치 수치와 시작 참가자를 확정할 때의 접속 예외는 별도 설계입니다.
- 복구할 수 없는 역할 부족만으로 자동 실패시키거나 재시작 버튼으로 넘기지 않습니다. 협동 필수 구간 주변에 실제로 사망할 수 있는 방법을 두고 실제 전멸 후 기존 재도전 흐름으로 갑니다. 용암·몬스터는 예시이며 모든 지역에 둘 다 배치하는 요구가 아닙니다.
- 각 역할 위치에 남은 사람이 사망 경로에 접근할 수 있는지 Levels와 검증합니다. 닫힌 문·일방통행·장치 상태·몬스터 부재/공격 불가·랜덤 연결로 경로가 막히는 경우를 확인합니다. 별도 솔로 모드의 범위는 이번 답변으로 정하지 않습니다.

상세 규칙: [출구와 팀 점수](../../../../Docs/DESIGN-0001-StageExit.md).

## 문제가 생겼을 때

필수 조건, 구간 시작 참가 명단, 현재 생존 인원, 입력 횟수, 장치 상태, 문 개방 결과를 확인합니다. 시작 인원과 현재 생존 인원을 같은 값으로 취급하지 않습니다.

협동 필수 구간에서 혼자 통과하지 못하는 것 자체는 의도한 규칙일 수 있습니다. 구간의 조건과 실제 역할 인원을 먼저 대조합니다. 주변 사망 경로가 없어 재도전할 수 없거나, 위험물은 있어도 남은 사람이 접근·사망할 수 없거나, 혼자 수행 가능한 구간까지 막힌 경우는 별도로 조사합니다. 실제 전멸 뒤 전환이 안 되면 StartandExit를 확인합니다. 아직 실제 발생한 버그를 뜻하지 않습니다.

작업 지시 예시: “Puzzles에서 두 스위치를 작동했는데 문이 열리지 않는 조건을 확인하고, 해당 Levels 배치도 함께 점검해주세요.”
