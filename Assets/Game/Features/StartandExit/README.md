# StartandExit — 시작·종료와 회차 진행

## 담당 범위

게임 시작·챕터 도전·스테이지 전환·출구·전멸·재시작·팀 정산·다음 구간 부활을 담당한다. 영구 해금·업적·설정은 Save가 관리한다.

## 확정 규칙

- 개방된 출구에 한 명이 유효 진입하면 클리어가 성립한다.
- 최초 진입부터 최대 5초 집계하며, 구간 시작 참가자 전원 도착 시 조기 마감한다.
- 사망·이탈로 명단을 줄이지 않는다. 진입자는 안전 대기하며 밖으로 나가지 않는다.
- 실제 도착 인원 보너스를 팀 총점에 더한다. 1인 보너스 0, 별도 전원 보너스·인원 비율 보정·몬스터 처치 점수 없음.
- 속도 평가 종료는 집계 마감이다. 총점 우선·동점이면 빠른 기록 우선.
- 공개 협동 랭킹은 기록 시작 4인 기준. 일반 이탈·사망·일부 미탈출만으로 클리어 팀 기록을 제외하지 않는다.
- 미탈출자는 다음 구간에서 부활한다. 협동 개인 점수·개인 랭킹 없음.
- 전멸 시 런 실패·로비 복귀, 점수·임시 진행 초기화. 재시작은 해당 챕터 처음부터이며 영구 해금은 유지한다.
- 방장 이전으로 서버의 타이머·런 상태·점수를 초기화하지 않는다.

상세 판정은 [출구와 팀 점수](../../../../Docs/DESIGN-0001-StageExit.md), 미정 값은 [상태 문서](../../../../Docs/PROJECT_STATE.md)에서 관리한다.

## 문제가 생겼을 때

[시스템 구조](../../../../Docs/ARCHITECTURE.md)의 상태 전이·단일 정산 계약과 [파이프라인](../../../../Docs/PIPELINE.md)의 게임 회귀 목록을 함께 봅니다. 현재 자동 검사는 기획 문서 대상이며 이 기능의 게임 테스트는 미구현입니다.

현재 챕터·스테이지, 참가자 상태, 종료 원인, 회차 점수, 초기화 전후의 해금 기록을 확인합니다. 미정인 정산·전환·부활 예외는 기획 확인 후 수정합니다.

출구 문제는 클리어 판정·속도 평가 종료·인원 보너스·랭킹 등록 자격을 구분해서 확인합니다. 향후 진단에는 기록/구간 시작 명단, 참가자 상태, 최초 진입·마감 시각, 마감 이유(5초 만료/구간 시작 참가자 전원 도착), 유효 도착자·탈락자 명단, 적용 규칙 버전과 항목별 점수를 연결할 수 있게 설계합니다. 현재 이러한 로그가 구현됐다는 뜻은 아닙니다.

작업 지시 예시: “StartandExit에서 4명 모두 들어왔는데도 5초를 전부 기다리는지 확인해주세요. 조기 집계 마감 시각을 속도 점수에도 사용하는지, 계산·로딩이 늦어져 평가 시간이 늘어나는지도 분리해 확인해주세요.”

작업 지시 예시: “StartandExit에서 첫 진입으로 클리어와 5초 제한이 시작되는지 확인해주세요. 실제 도착 인원으로만 팀 보너스를 계산하고 별도의 전원 보너스를 더하지 않는지, 미도착자가 다음 구간에서 부활하는지도 Player·Online과 대조해주세요.”

작업 지시 예시: “StartandExit에서 5챕터 전멸 후 점수는 초기화되지만 해금한 5챕터는 유지되는지 Save와 함께 확인해주세요.”

## 현재 프로토타입 구현 파일

| 실제 파일 | 역할 | 확인 방법 |
|---|---|---|
| `PrototypeExitScoring.cs` | Chapter01 출구 트리거, 도착자 집계, 팀 점수 표시용 로컬 흐름 | `PrototypeChapter01.unity`에서 출구 접근 및 HUD 확인 |

현재 구현은 로컬 흐름 확인용이며 운영자 전용 서버의 최종 판정 구현이 아닙니다. 5초 집계·전원 도착·전멸·랭킹의 정식 계약은 기존 설계 문서와 실제 서버 구현을 기준으로 별도 검증합니다.

기능 전용 파일은 이 폴더 안에 둡니다. 파일이 늘어나면 필요한 범위에서 `Scripts`, `Prefabs`, `Data`로 나눕니다.
