# Bugs — 버그 관리

증상, 재현 조건, 확인된 원인과 수정 결과를 한 기록에서 추적합니다. “추정한 원인”과 “확인된 원인”을 구분합니다.

## 사용 방법

1. [폴더 지도](../FOLDER_MAP.md)의 증상 표에서 처음 조사할 폴더를 찾습니다.
2. [BUG_TEMPLATE.md](BUG_TEMPLATE.md)를 참고해 `BUG-번호-짧은제목.md`를 만듭니다.
3. 재현 순서·기대 결과·실제 결과·게임 버전·담당 폴더를 기록합니다.
4. 수정 시 실제 파일과 관련 유지보수 작업을 연결합니다.
5. 같은 재현 조건으로 다시 확인하고, 영향받는 기능의 결과를 남깁니다.
6. 해결한 기록은 지우거나 새 파일로 복제하지 않고 상태와 이력을 갱신합니다.

## 상태

접수 → 재현 확인 → 수정 중 → 검증 대기 → 해결.

정보 부족, 재현되지 않음, 보류는 이유와 다음 확인을 기록합니다. “재현되지 않음”을 자동으로 해결로 처리하지 않습니다.

버그 상태와 테스트 판정은 분리합니다. 버그를 `해결`로 바꾸려면 동일 조건의 수정 파일·커밋·실행 환경·관련 테스트 또는 수동 증거를 기록합니다. 증거가 없거나 환경이 준비되지 않았으면 `검증 대기` 또는 `보류`로 유지합니다.

분류는 기능 오류·환경 오류·데이터/저장·온라인·보안·운영·기획 미정으로 나눕니다. 기획 미정은 임의 구현으로 닫지 않고 결정이 필요한 담당 채팅과 영향 범위를 연결합니다.

기능 우선순위(P0~P3)와 실제 영향(진행 차단·데이터 소실·연결 문제·표시 문제 등)을 각각 적습니다.
