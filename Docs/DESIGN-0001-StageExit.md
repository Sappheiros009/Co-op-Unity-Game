# 출구와 팀 점수 설계

문서 ID: DESIGN-0001 · 버전: 1.0 · 2026-09-17 · 확정 규칙  
담당: StartandExit · 연계: Player, Cooperation, Puzzles, Online, Save, UI, Levels

## 목적

한 명이 출구에 도달해도 팀은 클리어할 수 있고, 더 많은 동료가 함께 탈출할수록 팀 보너스를 얻는다. 클리어 성립, 도착자 집계, 점수 정산, 다음 구간 전환을 각각 관리한다.

## 판정 규칙

| 항목 | 확정 내용 |
|---|---|
| 출구 개방 | 해당 구간의 필수 장치·퍼즐 조건 충족 |
| 클리어 성립 | 살아 있는 참가자 한 명의 유효 진입 |
| 판정 주체 | PlayFab에서 실행되는 운영자 전용 게임 서버 |
| 최초 진입 | T0와 최대 마감 T0+5초를 한 번 기록 |
| 조기 마감 | 2~4인 모두 구간 시작 참가자 전원이 유효 진입 |
| 참가 기준 | 시작 명단 고정. 사망·이탈로 줄이지 않음 |
| 진입자 | 안전한 탈출 대기 상태. 다시 밖으로 나가지 않음 |
| 미도착자 | 집계 종료 시 탈락, 다음 스테이지에서 부활 |
| 늦은 진입 | 마감 연장·도착 인원 소급 증가 없음 |
| 정산 | 같은 구간 결과를 한 번 확정·저장 |

서버에서 유효 진입을 확인한 시점을 사용한다. 화면 연출, 로딩 완료, 클라이언트 타이머가 마감을 변경하지 않는다. 정확한 경계 tick와 지연 보정은 [상세 결정 목록](PROJECT_STATE.md)에서 관리한다.

## 상태 흐름

| 상태 | 전환 사건 | 결과 |
|---|---|---|
| 준비 | 참가자와 구간 구성 확정 | 구간 시작 명단 고정 |
| 진행 | 필수 장치 조건 충족 | 출구 개방 |
| 출구 개방 | 최초 유효 도착 | 클리어 성립·최대 5초 집계 시작 |
| 집계 | 추가 유효 도착 | 도착 집합에 한 번 추가 |
| 집계 | 시작 명단 전원 도착 또는 5초 만료 | 도착 집합·마감 시각 고정 |
| 정산 | 서버가 팀 결과 확정 | 팀 점수·기록 저장 |
| 전환 | 다음 구간 준비 | 미탈출자 부활 |
| 클리어 전 진행 | 생존자 없는 전멸 | 런 실패·로비 복귀 |

출구에 안전하게 진입한 플레이어를 사망자로 취급하지 않는다. 전멸 후 다시 시작하면 해당 챕터 처음부터 진행하고 런 점수를 초기화한다. 영구 챕터 해금·업적·설정은 유지한다.

## 팀 점수와 기록

1. 실제 도착 인원별 보너스를 팀 총점에 더한다. 한 명 도착 보너스는 0이다.
2. 인원 비율 보정과 별도의 전원 보너스는 적용하지 않는다.
3. 몬스터 처치 점수는 없다.
4. 속도 평가는 도착 집계가 종료된 시점까지이며 총점 우선·동점이면 더 빠른 기록 우선이다.
5. 공개 협동 랭킹은 기록 시작 4인 기준이다. 일반 이탈·사망·일부 미탈출로 클리어 팀 기록을 제외하지 않는다.
6. 팀 실패 기록은 클리어 랭킹에 넣지 않는다. 협동 개인 점수·개인 랭킹은 만들지 않는다.
7. 서버가 승인한 팀 런 결과만 저장한다. 결과는 팀·참가자·챕터·버전과 연결한다.

배점과 시간 시작점·단위·환산식은 미확정이다. 기존 예시 숫자는 밸런스 데이터에 사용하지 않는다. 보스·장치 점수와 완전 동점 처리도 상세 결정 대상이다.

## 협동 필수 구간

필요 역할 수는 구간 시작 인원에 맞추며 사망으로 줄이지 않는다. 역할이 부족하면 통과할 수 없고 주변 사망 경로로 실제 전멸 후 재도전한다. 자동 실패나 재시작 버튼은 적용하지 않는다. 협동 필수가 아닌 구간은 혼자 오래 걸려도 수행할 수 있다.

Levels·Puzzles·MapGeneration은 사망 경로의 접근성을 함께 검증한다. 출구 개방에 역할 협동이 필요하더라도 출구에 전원이 들어가야 클리어하는 규칙으로 바뀌지 않는다.

## 확인 사례

| 상황 | 기대 결과 |
|---|---|
| 4인 시작, 1인만 도착 | 클리어 성립, 5초 후 정산, 도착 보너스 0 |
| 2인 시작, 2인 도착 | 즉시 집계 종료, 실제 2인 보너스 |
| 4인 시작, 1인 이탈, 3인 도착 | 시작 명단 유지, 5초까지 집계, 3인 보너스 |
| 4인 시작, 1인 사망, 3인 탈출 | 팀 기록 자격 유지, 사망자는 다음 구간 부활 |
| 같은 도착 요청 재전송 | 도착 인원·정산을 중복 증가시키지 않음 |
| 마감 후 도착 | 확정된 결과 유지 |
| 필수 역할 인원 부족 | 자동 완화 없음, 실제 전멸 후 재도전 가능 |
| 방장 이탈 | 방장 역할 이전, 서버 타이머·점수 유지 |

이 표는 구현 시 검증할 기준이다. 실제 플레이 검증 결과는 [Testing](Testing/README.md)에 기록한다.
