## 현재 확인된 사용자 요구

다음 내용은 이 설계에서 유지한다.

- 저품질 또는 단순 임시 외형을 목표로 하지 않는다. 고품질 캐릭터 에셋을 지향한다.
- 고품질은 사실적인 리얼리즘이 아니라 판타지 이세계 분위기의 고품질 스타일라이즈드 방향으로 해석한다.
- 저사양 PC에서도 안정적으로 플레이할 수 있도록 시각 품질과 렌더링 비용을 함께 설계한다.
- 손, 발, 몸통, 머리·얼굴 등 주요 파츠를 서로 구분한다.
- 눈·입·장식·목걸이처럼 교체·표정·상호작용에 영향을 주는 부위는 개별 접근 가능한 구조를 우선한다.
- 몸이 늘어나거나 크게 변형되는 기능은 현재 필수 요구로 두지 않는다. 필요성이 확인되면 별도 설계한다.
- 캐릭터의 세부 외형·재질·리깅·UV 방식은 AI가 임의로 확정하지 않고 사용자와 조율한다.

## 프론트엔드 최종 결정권

이 문서에서 프론트엔드는 플레이어가 보고·듣고·느끼는 클라이언트 경험을 의미한다. 다음 항목은 AI가 추천안을 만들 수는 있지만 최종 확정은 사용자 승인으로만 처리한다.

| 사용자 최종 결정 항목 | AI가 제공할 수 있는 것 |
|---|---|
| 캐릭터·몬스터·보스 외형·실루엣·색·재질·장식 | 레퍼런스 분석, 후보안 비교, 제작 비용·성능 영향 |
| 지역의 판타지 분위기·색감·랜드마크 | 무드보드 구성, 스타일 충돌 검사, 최적화 대안 |
| VFX·SFX·음악·애니메이션 연출 | 후보 목록, 가독성·반복 피로·성능·라이선스 검토 |
| UI/UX 레이아웃·스타일·폰트·아이콘·정보 표시 | 접근성·해상도·현지화·유지보수 검토 |

AI 추천 통합안의 `A01`, `B01~B03`, `C01~C04`, `D01~D06`은 위 사용자 결정 항목에 포함되므로 추천 후보일 뿐 확정안이 아니다. 사용자가 명시적으로 승인하기 전에는 최종 디자인·구매·외주·제작 명령으로 사용하지 않는다.

LOD·텍스처 크기·Material Slot·메시 구조·파일 형식·라이선스·버그 추적 방식은 기술 추천 대상으로 관리한다. 다만 기술 최적화 때문에 외형·사운드·연출이 바뀌는 경우에는 변경 내용을 사용자에게 먼저 제시하고 승인받는다.

## 캐릭터 파츠 구성 기준 초안

권장 기본 계층은 다음과 같다.

```text
Character
├─ Body_Torso
├─ Head
├─ Face
│  ├─ Eye_L
│  ├─ Eye_R
│  └─ Mouth
├─ Hand_L
├─ Hand_R
├─ Foot_L
├─ Foot_R
├─ Accessory
└─ Necklace
```

이 계층은 최종 오브젝트 수를 확정한 것이 아니라, 파츠별 제작·검수·교체가 가능해야 한다는 기준이다. 실제 메시를 완전히 분리할지, 일부를 같은 메시 안의 별도 파츠·재질 슬롯으로 관리할지는 사용자 선택과 성능 검토 후 결정한다.

```text
에셋 스펙
→ 앞·뒤·좌·우·위·아래 레퍼런스
→ 파츠 블록아웃
→ 하이폴리 모델
→ 게임용 리토폴로지
→ 재질·텍스처 아키텍처

→ 하이폴리→로우폴리 베이크

→ 애니메이션

```

### 단계별 산출물과 중단 기준

| 단계 | 산출물 | 다음 단계로 넘어가기 전 확인 |
|---|---|---|
| 에셋 스펙 | 역할·파츠·동작·재질 목록 | 미정 외형을 AI가 임의로 추가하지 않았는가 |
| 레퍼런스 | 6방향 도면·재질 참고표 | 모든 방향의 비율과 파츠 위치가 일치하는가 |
| 블록아웃 | 파츠별 기본 메시 | 실루엣·카메라 노출·파츠 경계가 맞는가 |
| 하이폴리 | 세부 조형 원본 | 레퍼런스와 다른 세부가 임의로 생기지 않았는가 |
| 리토폴로지 | 게임용 메시 | 애니메이션 변형·UV·충돌 제작이 가능한가 |
| 텍스처 구조 | Material Slot·Texture Set·마스크 목록 | Unity 렌더 파이프라인 미정 부분을 고정하지 않았는가 |
| UV | 심·UV 섬·패킹 결과 | 늘어짐·겹침·여백 오류가 없는가 |
| 베이크 | Normal·AO·Curvature·ID 등 | 파츠 경계와 표면 디테일이 깨지지 않는가 |
| 리깅 | Armature·Weight·Shape Key 후보 | 손·발·얼굴 파츠가 의도대로 움직이는가 |
| 애니메이션 | 상태별 Animation Clip | 이동·벽 타기·구조·부활에서 메시가 찢어지지 않는가 |
| Unity 검증 | Prefab·재질·Animator·검증 기록 | 목표 Editor에서 실제 임포트 결과를 확인했는가 |

## 파츠 분리 제작 규칙 초안

- 몸통, 머리, 양손, 양발은 최소한 논리적으로 분리된 파츠로 관리한다.
- 눈·입은 표정 변경 또는 교체 가능성을 고려해 별도 접근 가능하게 관리한다.
- 장식과 목걸이는 본체 메시와 분리해 교체·표시·숨김이 가능하도록 한다.
- 파츠 이름에는 좌우가 필요한 경우 `_L`, `_R`을 사용한다.
- 파츠마다 원점·피벗·재질 슬롯·검수 상태를 기록한다.
- 파츠가 분리되어 있어도 게임에서 반드시 분리 렌더링해야 하는 것은 아니다. 최종 성능 검토에서 병합할 수 있지만 원본 제작 파일의 추적 가능성은 유지한다.
- 몸 늘어남·눌림·Shape Key는 필수 기준이 아니라 선택 기능으로 관리한다.

## AI 작업 명령 공통 형식

AI에게 Blender 작업을 요청할 때는 한 번에 전체 제작을 지시하지 않는다.

```text
역할:
현재 단계:
입력 자료:
이번 단계에서 할 일:
이번 단계에서 하지 말 일:
생성·수정할 파일:
검수 기준:
불확실한 부분 처리:
중단 조건:
```

AI는 다음을 지켜야 한다.

- 사용자 제공 레퍼런스와 확정 기획을 먼저 사용한다.
- 미정인 외형·능력·장식·색상·파츠를 추측하지 않는다.
- 현재 단계 밖의 모델링·텍스처·리깅을 연쇄 실행하지 않는다.
- 생성한 오브젝트·파일·재질·변경 내용을 보고한다.
- 오류나 레퍼런스 불일치가 있으면 멈추고 확인을 요청한다.
- Blender 원본을 덮어쓰기 전에 저장 위치와 변경 범위를 명시한다.

## 캐릭터 제작 방식 선택지

### 결정 1 — 파츠 분리 수준

- A. 몸통·머리·손·발을 별도 메시로 만들고 눈·입·장식도 개별 접근 가능하게 관리한다. **추천**
- B. 몸통·머리·손·발만 별도 메시로 만들고 눈·입은 재질 또는 Shape Key로 관리한다.
- C. 눈·입·장식까지 모두 완전 교체형 모듈로 만든다. 제작·관리 비용이 가장 크다.

### 결정 2 — Blender 모델 제작 방식

- A. 실제 레퍼런스를 바탕으로 Blender에서 직접 모델링하고 AI는 도면 정리·반복 작업·검수 보조에 사용한다. **추천**
- B. AI가 생성한 3D 메시를 Blender에서 리토폴로지·UV·리깅한다.
- C. 기본 형태만 AI 메시를 사용하고 핵심 파츠는 Blender에서 다시 제작한다.

### 결정 3 — 텍스처 제작 방식

- A. Blender에서 기본 텍스처·재질을 제작하고, 필요할 때만 외부 PBR 도구를 검토한다. **추천**
- B. 모든 텍스처를 Blender에서 직접 제작한다.
- C. AI 텍스처를 바탕으로 만들고 Blender에서 수동 검수·수정한다.

## 전체 에셋 선택지

이 절은 캐릭터만이 아니라 게임 제작에 필요한 시각·음향·연출 자원의 선택을 한 번에 조율하기 위한 작성 구역이다. 아래 선택지는 아직 확정안이 아니며, `추천` 표시는 수석 개발 관점의 검토 의견일 뿐이다. 사용자가 선택한 항목만 확정 후보가 된다.

### 선택 및 확정 규칙

- `A01`처럼 ID 단위로 하나를 선택한다. `[복수 선택]`으로 표시된 항목만 여러 개를 선택할 수 있다.
- 공통 선택과 특정 에셋의 예외 선택이 충돌하면, 먼저 공통 선택을 적용하고 예외 사유·영향·검수 방법을 기록한다.
- 고퀄리티 목표는 유지한다. 다만 품질을 높이는 방법이 런타임 성능·로딩·네트워크 동기화·제작 기간에 미치는 영향을 함께 검토한다.
- 유료 에셋·외주·구독은 자동 결제하지 않는다. 후보의 가격, 상업적 사용권, 수정·재배포 허용 범위, Unity 적용 가능성을 확인한 뒤 사용자 승인을 받는다.
- 무료라는 이유만으로 채택하지 않으며, 유료라는 이유만으로 품질을 보장하지 않는다.
- AI가 만든 초안은 사용자가 제공한 레퍼런스와 확정된 기획에 맞는지 사람이 검수한 뒤에만 제작물로 승격한다. AI는 미정인 외형·색상·기능·세계관을 임의로 추가하지 않는다.
- 선택된 에셋은 원본 파일, 게임용 파일, 라이선스 근거, 담당 폴더, Unity 적용 결과를 서로 추적할 수 있어야 한다.

### A. 공통 아트·조달 정책

#### A01 — 전체 아트 스타일

- A. 고퀄리티 스타일라이즈드: 선명한 실루엣과 개성 있는 재질을 사용하고, 슬라임 캐릭터와 지역별 분위기를 함께 살린다. **추천 후보**
- B. 고퀄리티 세미 리얼: 실제 재질·조명 표현을 강화하되 캐릭터와 환경은 읽기 쉽게 단순화한다.
- C. 고퀄리티 리얼리즘: 실제에 가까운 재질·조명·표면 디테일을 우선하며 제작·최적화 비용이 가장 커질 수 있다.

#### A02 — 에셋 조달·제작 방식

- A. 핵심 에셋은 Blender에서 직접 제작하고, 반복 작업과 검수만 AI가 보조한다. **추천 후보**
- B. 상업용 유료 에셋을 구매해 전체 스타일을 통일하고, 핵심 파츠는 수정·재제작한다.
- C. 전문 제작자에게 맞춤 외주하고, 내부에서는 사양·검수·Unity 적용을 담당한다.
- D. 에셋 종류에 따라 A~C를 혼합한다. 캐릭터·보스·핵심 기믹은 직접/외주, 배경 장식·일반 효과는 구매하는 방식이다. **추천 후보**

#### A03 — 품질·성능 목표

- A. 고품질 기본 등급 + PC 사양별 LOD·텍스처·그림자 품질 단계 제공. **추천 후보**
- B. 최고 품질을 우선하고 고사양 PC를 기준으로 제작한다.
- C. 중간 품질을 기준으로 제작하고, 일부 핵심 에셋만 고품질로 유지한다.

#### A04 — AI 사용 범위

- A. 레퍼런스 정리, 이름 부여, 반복적인 Blender 작업, 검사표 작성만 허용한다. 핵심 모델과 최종 외형은 사람이 확정한다. **추천 후보**
- B. AI 생성 모델·텍스처를 초안으로 사용하되, Blender에서 핵심 파츠를 재구성하고 사람이 최종 승인한다.
- C. AI 생성물을 넓게 사용하되, 모든 결과물에 레퍼런스 일치·저작권·토폴로지·UV·Unity 검수 게이트를 둔다.

#### A05 — 유료 자원 사용 정책

- A. 고품질과 제작 기간에 유리하면 유료 구매를 검토하되, 항목별로 사용자 승인 후 구매한다. **추천 후보**
- B. 무료·오픈 라이선스 자원만 사용한다.
- C. 핵심 캐릭터·보스·테마 음악은 맞춤 외주를 우선하고, 일반 자원은 구매 또는 직접 제작한다.

#### A06 — 라이선스 승인 기준

- A. 상업적 사용·수정·게임 패키지 배포가 허용되고, 필요한 경우 프로젝트 내 라이선스 문서를 보관할 수 있는 자원만 사용한다. **추천 후보**
- B. 프로토타입 전용 라이선스와 출시용 라이선스를 분리해 관리한다.
- C. 라이선스가 불명확한 자원은 사용하지 않고 대체 후보를 찾는다.

### B. 캐릭터·몬스터·보스 에셋

#### B01 — 플레이어 캐릭터 구성

- A. 하나의 고품질 기본 슬라임 모델을 만들고 색상·표정·장식·목걸이·소품을 모듈화한다. **추천 후보**

- C. 기본 모델은 공유하되 머리·얼굴·손·발·장식 조합을 여러 세트로 제공한다.

#### B02 — 몬스터 제작 구성

- A. 몬스터마다 고유 실루엣과 핵심 파츠를 직접 제작한다. 일반 장식만 재사용한다. **추천 후보**
- B. 공통 베이스 메시와 리깅을 만들고, 머리·팔·무기·등 장식·재질로 변형한다.
- C. 상업용 베이스를 구매한 뒤 게임의 레퍼런스에 맞게 리토폴로지·재질·애니메이션을 수정한다.

#### B03 — 보스 제작 구성

- A. 보스는 일반 몬스터와 분리된 전용 모델·전용 리깅·전용 VFX를 만든다. **추천 후보**
- B. 대형 공통 베이스와 모듈 파츠를 만들고, 보스별 핵심 파츠만 새로 제작한다.
- C. 외주 또는 구매 모델을 기반으로 하되, 실루엣·약점 표현·상호작용 지점·애니메이션을 프로젝트 전용으로 재작업한다.

#### B04 — 메시 제작 파이프라인

- A. 하이폴리 조형 → 게임용 리토폴로지 → 베이크 → LOD 제작. **추천 후보**
- B. 처음부터 게임용 메시로 제작하고 재질·노멀·마스크로 디테일을 표현한다.
- C. 핵심 캐릭터·보스는 A, 일반 몬스터·장식은 B로 분리한다.

#### B05 — UV·Texture Set 구성

- A. 몸통·머리·얼굴·손발·장식을 목적에 따라 여러 Material Slot/Texture Set으로 분리한다. 파츠 교체와 버그 추적이 쉽다. **추천 후보**
- B. 하나의 통합 Texture Set으로 묶어 드로우콜과 관리 대상을 줄인다.
- C. 핵심 고해상도 에셋에만 여러 세트 또는 UDIM을 사용하고, 일반 에셋은 A 또는 B로 관리한다. Unity 적용 호환성은 별도 검증한다.

#### B06 — 재질·맵 구성

- A. Base Color, Normal, Roughness 또는 Smoothness, Metallic, AO를 기본으로 한다. **추천 후보**
- B. A에 젖음·투명도·발광·상처·팀 색상·상태 표시용 마스크를 추가한다.
- C. 피부·점액의 산란·투과·고급 셰이더까지 적용하되, 목표 렌더 파이프라인에서의 호환성을 먼저 검증한다.

#### B07 — 리깅·변형 방식

- A. 공통 본 구조 + 파츠별 스키닝 + 필요한 부위만 제어 본을 추가한다. **추천 후보**
- B. A에 얼굴·눈·입·손·발 Shape Key를 추가한다.
- C. IK·모듈형 리그·고급 보조 제어까지 구성한다. 제작 시간과 유지보수 비용이 가장 크다.

늘어남·눌림 표현은 위 선택과 별도의 선택 기능이다. 사용자가 확정하기 전까지 필수 요구사항으로 승격하지 않는다.

#### B08 — 애니메이션 제작 경로

- A. Blender에서 프로젝트 전용 핵심 동작을 직접 제작한다. 이동·점프·벽 타기·구조·부활·출구 대기·상호작용을 우선한다. **추천 후보**
- B. 모션 캡처 또는 상업용 애니메이션을 리타게팅한 뒤 슬라임 신체 구조에 맞게 직접 수정한다.
- C. 공통 이동은 구매·리타게팅하고, 협동·지역 기믹·보스·감정 표현은 직접 제작한다.

#### B09 — LOD·충돌·소켓

- A. 고품질 원본과 함께 LOD0·LOD1·LOD2, 단순 충돌, 상호작용 소켓을 제작한다. **추천 후보**
- B. 가까운 시점의 고품질 모델 하나를 우선하고, 실제 성능 문제가 확인된 에셋만 LOD를 추가한다.
- C. 플랫폼·품질 단계별로 메시·텍스처·그림자·충돌을 함께 교체하는 스케일러블 구성을 만든다.

- B. 고품질 VFX 팩을 구매하고 색·스케일·재생 타이밍·셰이더를 프로젝트에 맞게 수정한다.
- C. 모든 VFX를 직접 제작해 지역·몬스터·보스의 시각 언어를 통일한다.

핵심 VFX에는 위험 구역, 발판 상태 변화, 몬스터 인식·추격 예고, 구조·부활, 장치 상태, 출구 집계·안전 대기를 포함할 수 있으나, 실제 기능 포함 여부는 관련 기획 확정 후 결정한다.

#### D02 — SFX 제작 방식

- A. 상호작용·장치·발판·몬스터·구조·부활·출구·UI 확인음처럼 규칙을 전달하는 핵심 SFX는 직접 제작 또는 맞춤 제작하고, 일반 환경음은 검증된 라이브러리를 사용한다. **추천 후보**
- B. 상업용 SFX 라이브러리를 구매해 전체 사운드 스타일을 정리한다.
- C. 현장 녹음·직접 디자인을 기반으로 모든 주요 SFX를 제작한다.

#### D03 — 음악 제작 방식

- A. 지역별 독립 곡은 맞춤 작곡 또는 상업적 사용권이 명확한 라이선스 곡으로 구성한다. **추천 후보**
- B. 하나의 테마를 편곡해 지역별 변주로 만든다.
- C. 무료·유료 라이브러리 곡을 조합하되, 게임 배포·방송·영상 사용권을 곡별로 확인한다.

#### D04 — UI·아이콘·폰트 제작 방식

- A. 조작·상태·위험·협동·출구·점수 정보를 전달하는 핵심 UI와 아이콘은 프로젝트 전용으로 제작하고, 일반 프레임·버튼은 구매 키트를 보완적으로 사용한다. **추천 후보**
- B. 상업용 UI 키트를 기반으로 전체 UI를 통일하고, 핵심 화면만 직접 다시 제작한다.
- C. UI·아이콘·폰트·메뉴 전부를 직접 제작하거나 맞춤 외주한다.

#### D05 — 자막·현지화 에셋

- A. 텍스트 테이블·폰트·아이콘·자막 표시 규격을 초기에 정하고, 한국어를 기준으로 확장 가능한 구조를 만든다. **추천 후보**
- B. 한국어만 우선 구현하고 출시 전에 다른 언어 구조를 추가한다.
- C. 지원 언어별 폰트·줄바꿈·텍스트 길이·자막 안전 영역을 동시에 검증한다.

#### D06 — 조명·후처리·카메라 연출 에셋

- A. 지역별 조명 프리셋·볼륨·안개·색 보정·위험 강조 규칙을 직접 정의하고, 성능 단계별 대체값을 준비한다. **추천 후보**
- B. 구매한 환경·조명 프리셋을 기반으로 필요한 지역만 수정한다.

## AI 추천 통합안 — 승인 대기

사용자가 모든 항목을 직접 조합하지 않아도 되도록, 현재 확정된 프로젝트 방향과 제작 리스크를 기준으로 하나의 기본안을 제시한다. 아래 내용은 `AI 추천·승인 대기` 상태이며, 사용자는 전체 승인하거나 마음에 들지 않는 항목만 수정하면 된다.

단, 전체 추천안을 승인하더라도 프론트엔드 표현 항목은 별도의 사용자 승인 없이는 확정되지 않는다. 전체 승인은 기술·운영 기본안에 대한 검토 완료로 해석하고, 외형·UI·VFX·SFX·음악·연출은 사용자 레퍼런스 또는 명시적 승인 기록을 추가로 요구한다.

### 추천 결론

**판타지 이세계풍 고퀄리티 스타일라이즈드 아트 + 저사양 우선 스케일링 + 핵심 에셋 직접 제작 또는 맞춤 외주 + 반복 에셋 유료 구매 + Blender 원본 보존 + Unity용 최적화 변환**을 기본 전략으로 추천한다.

이 전략을 선택하는 이유는 다음과 같다.

- 슬라임 캐릭터·몬스터·보스·지역 랜드마크의 고유성을 유지할 수 있다.
- 상업용 에셋 팩을 그대로 섞었을 때 발생하는 스타일 불일치와 라이선스 추적 문제를 줄일 수 있다.
- 모든 것을 직접 제작하는 방식보다 반복 장식·일반 SFX·범용 VFX의 제작 시간을 줄일 수 있다.
- 원본 제작 구조와 Unity 런타임 구조를 분리해 고품질과 성능을 함께 관리할 수 있다.
- 사용자 제공 레퍼런스가 없는 부분을 AI가 임의로 확정하지 않으면서도, 반복 작업·검수·문서화를 자동화할 수 있다.

### 판타지 이세계풍 고퀄리티의 정의

이 프로젝트의 고퀄리티는 현실의 피부 모공·금속 반사·고해상도 표면을 그대로 재현하는 방식이 아니다. 다음 요소를 우선해 적은 렌더링 비용으로도 완성도와 분위기를 전달한다.

- 현실에 없는 실루엣·색 조합·재질 대비·발광 포인트로 이세계성을 만든다.
- 캐릭터의 손·발·얼굴·눈·입·장식을 가까운 거리에서도 읽을 수 있게 한다.
- 복잡한 표면 디테일을 늘리기보다 큰 형태, 색면, 명암, 재질 구분, 시선 유도용 VFX를 우선한다.
- 지역마다 팔레트·안개·조명·발광 색을 차별화하되, 공통 셰이더와 텍스처 규칙을 재사용한다.
- 현실적인 고급 셰이더보다 가벼운 스타일라이즈드 셰이더를 기본으로 하고, 고급 효과는 보스·랜드마크 등 제한된 대상에만 적용한다.

### 추천안에서 의도적으로 제외한 것

- AI가 생성한 모델·텍스처를 수정 없이 최종 에셋으로 사용하는 방식은 채택하지 않는다.
- 모든 에셋을 하나의 상업용 팩으로 통일하는 방식은 채택하지 않는다. 핵심 고유 에셋의 개성이 약해지고 라이선스 범위가 한 번에 복잡해질 수 있다.
- 모든 캐릭터 파츠를 항상 별도 GameObject와 별도 Material로 렌더링하는 방식은 채택하지 않는다. 원본 파츠 분리와 런타임 렌더링 분리는 다른 문제이며, 성능 검수 후 병합할 수 있어야 한다.
- UDIM·고급 산란·고비용 후처리는 기본값으로 고정하지 않는다. 필요한 보스·랜드마크에 한정해 Unity 목표 버전에서 검증한 뒤 적용한다.
- 고퀄리티를 포토리얼리즘·4K 텍스처·고밀도 메시·다수의 실시간 광원과 동일시하지 않는다. 판타지 스타일과 프레임 안정성이 우선이다.
- 무료 에셋만을 사용한다는 정책은 채택하지 않는다. 필요한 경우 유료·외주를 사용하되, 구매 승인과 라이선스 검수를 거친다.

### 추천 제작 순서

1. 플레이어 기본 슬라임의 레퍼런스와 파츠 구조를 확정한다.
2. 플레이어 1종을 기준으로 Blender 원본·UV·재질·리그·애니메이션·Unity Prefab까지 수직 슬라이스한다.
3. 수직 슬라이스에서 성능·파츠 교체·온라인 동작·버그 추적이 검증되면 몬스터와 보스에 공통 규칙을 확장한다.
4. 지역별로 핵심 랜드마크와 퍼즐 소품을 먼저 제작하고, 반복 환경·장식·일반 VFX·SFX는 구매 후보와 비교한다.
5. 후보 에셋은 실제 Unity 임포트와 라이선스 검토를 통과한 것만 채택한다.
6. 모든 에셋에 Asset ID와 완료 검수 기록을 연결한 뒤, 확정된 공통 규칙만 `Plan.md`로 승격한다.

## 추천안 검토·수정 양식

전체 항목을 다시 선택할 필요는 없다. 아래 첫 줄에 전체 승인 여부를 쓰고, 수정하고 싶은 항목만 적는다.

```text
추천안 처리: 전체 승인 / 일부 수정
수정할 ID:
수정 이유:
구매·외주에 대한 별도 조건:
추가로 반드시 반영할 사용자 요구:
```

기존의 세부 선택표와 후보 입력표는 추천안을 바꾸고 싶을 때만 사용한다. 사용자가 별도 수정을 하지 않은 추천 항목은 AI 검토 후에도 자동 확정하지 않고 `승인 대기`로 유지한다.

아래 양식에 선택지를 입력하면, AI는 선택 결과를 현재 확정 규칙·프로젝트 폴더·기술 파이프라인과 대조한다. 선택하지 않은 항목은 미정으로 남긴다.

```text
[공통]
A01 전체 아트 스타일:

결정 1 파츠 분리 수준:
결정 2 Blender 모델 제작 방식:

B01 플레이어 캐릭터 구성:
B02 몬스터 제작 구성:
B03 보스 제작 구성:
B04 메시 제작 파이프라인:

기타 직접 지시:
```

### 선택 후 AI 검토 절차

1. 입력된 선택지가 기존 확정 규칙과 충돌하는지 확인한다.
2. 캐릭터 파츠 분리, Blender 원본, UV·텍스처·리깅, Unity 임포트, 네트워크 동기화, 성능 단계의 연결을 확인한다.
3. 지역별 폴더와 담당 기능 폴더가 분리되어도 Asset ID와 README로 추적 가능한지 확인한다.
4. 유료·외주 후보는 가격·라이선스·납품 형식·수정 가능 범위·상업 배포 권리를 검토한다.
5. 선택 결과 중 확정 가능한 항목만 서술형 기획서로 바꾸고, 예산·후보 상품·렌더 파이프라인처럼 추가 근거가 필요한 항목은 `PROJECT_STATE.md`에 남긴다.
6. 확정 후에는 `Plan.md`, 담당 README, `FOLDER_MAP.md`, `PIPELINE.md`의 필요한 부분만 연결하고, 문서 검증을 실행한다.

### 에셋 완료 정의

에셋은 파일이 존재하는 것만으로 완료로 보지 않는다. 다음 조건을 모두 만족해야 완료 후보가 된다.

- 사용자가 확정한 레퍼런스·실루엣·파츠 구조와 일치한다.
- 고품질 목표에 맞는 모델·재질·텍스처·조명 결과를 확인했다.
- 원본과 Unity 게임용 파일의 관계를 추적할 수 있다.
- UV·Material Slot·Texture Set·리깅·애니메이션·LOD·충돌·소켓이 문서에 기록되어 있다.
- 라이선스와 상업 배포 가능 범위를 확인했다.
- 목표 Unity 버전에서 임포트하고 실제 플레이 구간에서 검수했다.
- 문제 발생 시 Asset ID와 재현 절차로 담당자가 수정 위치를 찾을 수 있다.
