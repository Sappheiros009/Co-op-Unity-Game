- 기준: Plan.md의 확정 규칙, 2026-09-18 전체 기획 프로토타입 제작 요청
- 작업 프로젝트: 이 저장소 자체의 Unity 6000.6.1f1 프로젝트

2026-09-20 개발 목표를 중단했다. 아래 후속 과제는 재개 승인 전에는 실행하지 않는다. 현재 결과는 [인계서](../PROTOTYPE_HANDOFF.md), 실제 GitHub·Notion 반영 여부는 [게시 상태](../PUBLISH_STATUS.md)에서 관리한다.

## 요구사항과 설계

로비 → 3D 대기실 → 선택 챕터(일반 구간 5개·협동 보스 구간 1개) → 이야기 씬 → 대기실을 연결한다. 7개 지역은 기본 도형·팔레트와 기능성 장치로 표현한다. UI·소리·외형은 사용자 최종 디자인 승인을 대신하지 않는 시험 표현이다.

| 책임 | 구현 경로 | 데이터 흐름 |
|---|---|---|
| 이동·체력 | Player, Core/Prototype/PrototypeParticipant | 입력 → 상태 검사 → 이동·다운·부활 |
| 협동·아이템 | Cooperation, Interaction, Items | 대상·거리·소지품 검사 → 장치/구조 결과 |
| 맵·장치 | MapGeneration, Puzzles, Monster | 시드 → 연결 검사 → 고정 방·변형 통로 → 장치 → 출구 |
| 런 | StartandExit, Core/Prototype/PrototypeGame | 고정 시작 명단 → 도착 집계 → 팀 정산 → 다음 구간/이야기 |
| 표시·저장 | UI, Save, Story | 상태 읽기 → 한글 안내·설정 → 버전 포함 로컬 파일 |
| 접속·운영 시험 | Online | 가상 참가자 연결/이탈·방장 이전·중복 요청/거리 검증 |
| 별도 프로세스 대기실 | Online, LocalNetwork.ps1 | 실제 연결 ID → 서버 승인/명단/준비 → 각 클라이언트 표시 |

현재 구현의 판정권은 로컬 시험 세션에 있다. PlayFab 운영자 전용 서버는 최종 서비스 구조이며, 미선택 네트워크 SDK·운영 계정·Steam App ID 없이 실제 온라인 서비스가 동작한다고 표시하지 않는다. 로컬 동료는 시험용이며 사용자에게 항상 표시한다.

시험용 밸런스는 별도 JSON에 두고 최종 기획 수치로 승격하지 않는다. 일반 전멸은 임시 진행·점수만 버리고 로비로 이동하며 영구 진행과 설정은 보존한다. 개별 다운·이탈로 협동 역할 수와 출구 기준 명단을 축소하지 않는다.

## 완료 확인

2026-09-19 추가 범위: Steam App ID·PlayFab 프로젝트가 아직 없어 로컬 전용 서버·다중 클라이언트부터 검증한다. 같은 PC의 별도 서버 프로세스와 2~4개 클라이언트를 분리하고, 서버가 판정하며 방장 이탈은 역할만 이전한다. 계정 생성·클라우드 배포·요금 발생·방화벽 변경·비밀 키 수집은 하지 않는다. 실제 통신 증거를 기존 로컬 시험 동료 테스트와 구분한다.

씬 생성, 컴파일, Windows 빌드, 실제 PlayMode 회귀, 렌더 캡처, 문서 검사를 수행한다. 결과와 미구현 범위는 [프로토타입 안내](../PROTOTYPE_GUIDE.md)에 기록한다.

16:02(KST) 통합 Full은 PlayMode 77/77, 일반 화면 11종, 별도 서버 + 2/3/4인 대기실, 과도 요청 클라이언트 격리까지 통과했다. 실제 전체 챕터 멀티플레이는 완료하지 않았다. 다음 단계는 기존 이동·상호작용·퍼즐·정산을 서버에서 실행하고 클라이언트는 조작 요청과 표시만 담당하게 연결하는 것이다. [TEST-0004](../Testing/TEST-0004-LocalNetwork.md)의 경계를 유지한다.

2026-09-19 마무리: 사용자 사용량 잔여 2%에 따른 요청으로 신규 기능 개발을 중단했다. 문서 검사기 자체 테스트는 C# 링크 대상도 격리 검사본에 포함하도록 보완한 뒤 20/20 통과했다. 4인 방장 프로세스 강제 종료 검사도 통과했으며, 상세 근거는 TEST-0004에 기록했다. 재개 시 첫 작업은 챕터 이동·협동 상호작용·출구 정산의 실제 서버 동기화다. 이번 작업에서 GitHub/Notion 게시와 Steam/PlayFab 연동은 수행하지 않았다.

## 재개 작업과 후속 게시

2026-09-19 활성 목표 재개 후 서버 플레이 연결을 진행한다. 직전 작업은 사용자 제공 개발 사이트를 실제로 확인·등록하고 문서 검사 690/690을 통과시킨 문서 진전이며, 챕터 동기화의 완료 근거가 아니다.

다음 구현은 기존 맵·이동·협동 규칙을 재사용한다. 각 참가자의 입력과 로컬 카메라를 분리하고, 서버는 연결 ID에 묶인 입력만 검증·실행한다. 클라이언트가 좌표·체력·소유품·점수·시간을 지정해 확정하는 구조는 추가하지 않는다. 단계별로 다인 입력 격리 → 실제 서버 실행 → 클라이언트 상태 표시 → 장치·정산·전환 → 2/3/4인 회귀를 검증한다.

사용자 추가 요청에 따라 프로토타입 구현·검증 완료 후 GitHub와 Notion에 반영한다. 게시 전 변경 파일·라이선스·비밀·생성 캐시 제외를 확인하고, 게시 후 커밋·페이지 내용을 다시 읽어 실제 반영을 검증한다. 확정 기획에는 질문·답변을 넣지 않으며 구현 결과·미검증 사항·참고자료는 구분한다. 아직 게시를 수행하지 않았고, 전체 목표의 완료 조건에는 이 후속 게시도 포함한다.

재개 후 입력 분리 단계: 독립 서버 플레이어·로컬 입력/카메라 격리·실제 플레이어 끌어올리기·서버 전환 알림·연결별 입력 버퍼를 구현하고 새 집중 검사 20/20과 전체 회귀 97/97을 통과했다. 이 단계 Windows 빌드·11개 화면·2/3/4인 대기실·과도 요청 격리 회귀도 통과했다. 실제 수정 파일과 실행 근거는 [TEST-0005](../Testing/TEST-0005-ServerPlayerControl.md)에 연결했다. 아직 실제 챕터 통신 경로에는 연결하지 않았으며 다음 단계는 입력 수신과 서버 월드 tick·클라이언트 표시를 연결하는 것이다.

후속 승인된 대기방 변경: 로비는 2D로 유지하고 슬라임 대기방은 직접 걷는 1인칭 3D 공간으로 전환한다. 일반 로컬 경로의 근접 챕터 선택 → 준비 장치 출발을 구현하고 해당 대기방 씬을 갱신했다. 최종 표지판 보강을 포함한 전체 PlayMode 110/110, 대기방·씬 흐름 집중 14/14, 문서 검사기 자체 테스트 22/22를 통과했다. 12회 가림·설정 복귀 반복과 30회 아이템 줍기·내려놓기 재사용도 포함한다. 최신 빌드·화면 결과는 [TEST-0006](../Testing/TEST-0006-WalkableWaitingRoom.md)에서 관리한다. 별도 서버 대기실은 아직 고정 시점 경로다.

최종 대기방 Windows 빌드는 19:15:44 KST 성공했고 19:16:46 KST 11종 렌더 캡처를 통과했다. 최종 로비·대기방 PNG를 직접 열어 표지판 겹침·뒤집힘 해소를 확인했다. 실행 파일은 `Build/FullPrototype/SlimeCoopPrototype.exe`다. 별도 서버 2/3/4인 방·과도 요청 격리의 후속 회귀는 마지막 표지판 수정 이전 빌드에서 통과했으며, 마지막 표지판 수정 이후의 네트워크 실행 완료로 확대하지 않는다.

이야기 전환은 현재 접속 중인 전원 동의로 확정했다. 방 모델은 런별 투표·철회·접속 종료자 제외를 처리하며 출구의 고정 시작 명단은 유지한다. 대기방 수정 시점에는 서버 월드 진입점과 클라이언트 표시가 미연결이었다. 이후 연결 결과는 아래 범위로 구분한다.

후속 서버 챕터 연결: `PrototypeNetworkBootstrap`에서 실제 서버 월드·입력 tick과 클라이언트 표시 전용 복제를 연결했다. 별도 서버 + 2/3/4인 시작/이동·입력 격리와 2/4인 실제 렌더를 확인했다. 담당 파일·검사·수정 중 발견한 문제는 [TEST-0007](../Testing/TEST-0007-NetworkWorldReplica.md)에 기록한다. 표시용 맵은 게임 판정·물리·동료 AI를 실행하지 않으며 클라이언트 키 설정은 서버 판정과 분리한다. 별도 서버의 직접 걷는 대기방·위험/사용 표현·전체 코스·이야기·영구 저장·예측/보정·원격 게시가 남아 있다.

이 단계 최종 결과: 전체 PlayMode 117/117(19:56:04 KST), Windows 빌드 성공(19:57:24 KST), 네트워크 7단계(19:59:36 KST), 일반 11종 렌더(20:00:18 KST), 문서 계약 788/788·검사기 자체 회귀 22/22. 직접 연 최종 PNG는 일반 로비·대기방과 네트워크 2/4인 챕터다. 전체 목표는 계속 진행 중이며 이번에도 GitHub·Notion 게시를 수행하지 않았다.

사용자 추가 작업 원칙: 더 나은 대안이더라도 별도 승인이 필요하면 해당 작업을 멈추고 추천안·비용·장단점·영향을 사이드바에서 비교해 승인을 요청한다. 승인 없는 구조·범위·최종 표현 변경으로 우회하지 않는다.

후속 완료/저장 연결: 서버 마감 결과를 표시용 세션값과 분리해 각 클라이언트의 해금·업적·로컬 팀 기록에 반영하고 발견한 기억도 동기화했다. 전용 서버는 개인 진행 파일을 쓰지 않는다. 전체 PlayMode 134/134, 별도 서버+2/3/4인의 챕터 1 시험 배치·5초 정산·동의 철회·저장·3D 복귀를 검증했다. 4인의 마지막 투표자 이탈은 투표에서만 제외하고 팀 기록의 시작 인원은 4명을 유지한다. 실제 수정 파일·빌드·디스크 대조와 남은 범위는 [TEST-0009](../Testing/TEST-0009-NetworkCompletion.md)에서 관리한다. 서버 시험 위치 배치를 실제 입력 완주로 승격하지 않으며 전체 목표·GitHub/Notion 게시는 계속 미완료다.

일반 로비 진입 연결: 시험 동료 시작을 유지하며 별도 로컬 서버 만들기·참가·취소/재시도·3D 대기방 전환을 추가했다. 생성자의 이탈로 서버를 종료하지 않으며 이름별 시험 저장을 배타 잠금으로 분리한다. 전체 150/150, 실제 2인·4인 메뉴 연결·방장 이전·동일 서버 재참가·2D 복귀·빈 서버 종료를 확인했다. [TEST-0010](../Testing/TEST-0010-LocalLobbyEntry.md)에 최종 실행 파일과 기존 경로 회귀를 기록한다. 전체 온라인 전멸/재도전·7챕터 실제 입력 완주·원격 게시는 별도로 남아 있다.

전멸 재도전 보완: 실제 위험 볼륨과 서버 참가자 발 위치의 판정으로 피해 누락을 수정하고, 클라이언트 전멸 시 임시 구간 정보도 한 번만 초기화한다. 전체 156/156과 같은 최종 빌드의 별도 서버+2/3/4인 전멸·2D 결과·3D 대기방·동일 챕터 1구간 재시작을 확인했다. 영구 저장 보존·이전 입력 거부·6장 화면 검수·실패 이력은 [TEST-0011](../Testing/TEST-0011-NetworkWipeRetry.md)에서 관리한다. 앞 문단의 온라인 전멸 재도전 미검증은 이전 단계 기록이며, 7챕터 실제 입력 완주·장시간 반복·외부 네트워크·원격 게시는 계속 남아 있다.
