# RUNBOOK-0001 — 릴리스·장애·복구 기준

상태: 기준 런북. 실제 운영 사건이나 배포 결과가 아님.

## 릴리스 전

1. 대상 커밋, Unity·패키지·콘텐츠·저장 버전, 플랫폼과 범위 고정.
2. 관련 `TEST`, `BUG`, `TASK`의 상태와 미검증 범위 확인.
3. 빌드 성공, 패키지 식별, 배포 성공, 이용자 접속 확인을 별도 기록.
4. 알려진 P0/P1 문제와 출시 차단 조건 확인.
5. 저장 변환·롤백·서버/클라이언트 호환 조건을 기록.
6. 비밀키·운영 자격증명 존재 여부만 확인하고 값은 문서·로그에 기록하지 않음.

## 장애 대응

1. `INC` 기록 생성, 발생 시각·버전·영향 세션·실행 식별자 고정.
2. 이용자 영향 완화와 원인 조사 분리.
3. 로그·덤프·요청 ID·빌드 해시 보존.
4. 추정 원인과 확인된 원인을 구분.
5. 다른 이용자·계정에 영향을 주는 자동 제재 금지.
6. 수정은 관련 `BUG`와 `TASK`에 연결.

## 복구와 롤백

- 롤백 조건: 진행 손실, 접속 불가, 저장 변환 실패, 서버 판정 불일치, 보안 오탐 등 사전에 기록한 조건 적용.
- 롤백 대상: 클라이언트 패키지, 서버 이미지/버전, 데이터 변환 경로, 설정 변경 범위를 분리 기록.
- 복구 확인: 접속, 재접속, 진행, 저장, 결과 전달을 같은 버전·환경에서 각각 기록.
- 변환 실패 시 원본 보존과 재시도·복구 경로를 우선하며 임의 초기화 금지.

## 제재·이의제기

서버 검증으로 확인된 핵은 세션에서 즉시 제한할 수 있다. 장기 계정 제재와 Steam Game Ban은 Steam 계정 및 검토된 증거를 운영자가 판단한다. 신고·지연·IP·전화번호·기기 일치만으로 자동 영구 제재하지 않는다. 이의제기·해제·오탐 복구 기록을 사건 ID에 연결한다.

## 기록 종료 조건

사건의 영향 범위, 조치, 실제 복구 증거, 남은 위험, 후속 `BUG/TASK`가 모두 기록된 뒤 종료한다. 미검증 범위가 남으면 종료 사유에 명시하며 전체 안정성으로 확대하지 않는다.
