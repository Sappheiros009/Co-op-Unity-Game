## 실제 구현 상태

중단 시점 최신 게임 변경은 **전멸 후 클라이언트 임시 정보 초기화와 실제 위험 영역의 서버 판정 보완**이다. 2D 로비·직접 걷는 3D 대기방·중앙 준비 장치 경로는 유지한다. 게임 회귀는 2026-09-19 23:05:27 KST **156/156** 통과했고, 비동기 상태 비교 QA 보완 후 Windows 빌드는 23:06:59 KST 성공했다. 해당 빌드의 실제 **2/3/4인 전멸 → 2D 결과 → 3D 대기방 → 같은 챕터 새 런** 검사는 23:14:55 KST까지 모두 통과했다. 12개 프로세스·영구 파일 보존·6장 PNG와 실패 이력은 [TEST-0011](Testing/TEST-0011-NetworkWipeRetry.md)에서 관리한다. 전체 프로토타입은 미완료이며 추가 개발은 중단했다.

이전 단계는 일반 2D 로비에서 같은 PC의 전용 서버 만들기·참가·취소/재시도·직접 걷는 3D 대기방 진입이었다. 기존 시험 동료 시작 경로를 유지한다. 실제 참가자는 이름별 시험 저장을 분리하고 같은 프로필의 동시 쓰기를 차단한다. 방을 만든 사람이 나가도 별도 서버는 유지된다. 당시 Windows 빌드는 22:02:01 KST, 전체 PlayMode **150/150**은 22:06:35 KST, 일반 메뉴의 실제 2인·4인 생성/참가/왕복/재참가는 22:07:38 KST 통과했다. 당시 실행 파일·PNG·기존 회귀·실패 이력은 [TEST-0010](Testing/TEST-0010-LocalLobbyEntry.md)에 기록한다.

앞선 **서버 완료 결과·참가자별 로컬 저장·이야기 합의·3D 대기방 복귀** 단계는 [TEST-0009](Testing/TEST-0009-NetworkCompletion.md)다. 당시 전체 134/134와 별도 서버+2/3/4인 전환 시험이 통과했다. 챕터 1에서는 서버가 시험 위치에 참가자·상자를 배치했으므로 실제 입력 코스 완주가 아니다. 4인 중 한 명의 저장 후 이탈·남은 3인 복귀·시작 4인 기록 보존을 확인했다. 직접 걷는 멀티 대기방의 125개 검사는 [TEST-0008](Testing/TEST-0008-NetworkWaitingRoom.md), 아래 110/117개 결과는 그보다 앞선 이력이다.

2026-09-19 통합 기획 프로토타입 재제작을 진행했다. 일반 로컬 실행의 슬라임 대기방은 직접 이동하는 1인칭 3D 공간으로 구현했고 로비는 2D로 유지한다. 챕터 선택 지점에서 고른 뒤 중앙 준비 장치에서 출발하며, 시험 동료의 준비는 자동이다. 로컬 대기방 기준선 당시 표지판 방향·장치·씬 흐름 집중 검사 14/14가 통과했다. 당시 대기방 회귀·Windows 빌드·화면 검수는 [TEST-0006](Testing/TEST-0006-WalkableWaitingRoom.md), 이전 서버 입력 분리 20개와 전체 97개 검사는 [TEST-0005](Testing/TEST-0005-ServerPlayerControl.md)에서 구분한다. 총 42구간의 가속 장치·정산·저장·스토리 복귀 검사는 제어된 입력·배치를 사용하므로 사람이 실제 창에서 완주했거나 전체 온라인 플레이가 동작한다는 증거가 아니다. 아래 2026-09-18 게시·빌드는 이전 기준선의 이력이다. 최신 원격 반영 여부는 [게시 상태](PUBLISH_STATUS.md)에서 별도로 확인한다.

사용자는 Steam App ID·PlayFab 프로젝트가 아직 없으므로 로컬 전용 서버·다중 클라이언트 검증을 먼저 진행하기로 선택했다. 클라우드 서비스·유료 자원은 생성하지 않는다. 기존 PlayFab 운영자 전용 서버의 최종 판정 방향은 유지한다. 시험 패키지의 도입은 정식 네트워크 패키지 확정과 구분한다.

대기방 표시 수정 당시 전체 PlayMode 회귀는 110/110 통과했다(2026-09-19 19:14:39 KST). 같은 소스의 Windows 빌드는 19:15:44 KST 성공했고 11종 렌더 캡처도 통과했다. 당시 최종 로비·대기방 PNG 두 장을 직접 확인했다. 문서 검사기 자체 테스트도 22/22 통과했다. 이후 서버 챕터 연결·키 안내 보강 단계의 전체 회귀는 117/117(19:56:04 KST), Windows 빌드는 19:57:24 KST 성공이었다. 각 결과는 게임 규칙·화면·문서 계약이라는 서로 다른 범위를 검증한다.

후속 로컬 네트워크 대기실은 별도 서버 + 실제 2인/3인/4인 클라이언트와 과도 요청 격리 검사에 통과했다. 준비·챕터 선택·명단 고정·방장 이탈·버전/정원/권한/중복 거부의 통신 증거이며 전체 챕터 플레이 동기화 증거가 아니다. [TEST-0004](Testing/TEST-0004-LocalNetwork.md)에서 검증 범위를, [TEST-0006](Testing/TEST-0006-WalkableWaitingRoom.md)에서 이번 회귀 시점을 구분한다.

서버 월드 실행·연결별 입력 수신·클라이언트 표시 전용 복제를 실제 실행 경로에 연결했다. 별도 서버 + 2/3/4인에서 챕터 시작·입력한 참가자만 이동·동일 서버/런·정상 종료와 2/4인 챕터 PNG를 확인했다. 챕터 복제 기준선은 [TEST-0007](Testing/TEST-0007-NetworkWorldReplica.md), 실제 참가자의 3D 대기방·근접 장치·입력 세대 분리는 [TEST-0008](Testing/TEST-0008-NetworkWaitingRoom.md)이다. 후속 [TEST-0009](Testing/TEST-0009-NetworkCompletion.md)에서 챕터 1의 서버 시험 배치·정산·결과 저장·이야기·복귀를 검증했고, [TEST-0011](Testing/TEST-0011-NetworkWipeRetry.md)에서 실제 위험 피해·전멸·새 런 재도전을 확인했다. 7챕터 실제 입력 코스 완주·지역 위험 표현·이탈/재접속과 전멸의 동시 경계·장시간 재도전·클라우드 저장 회귀는 남아 있다. 사용자 요청에 따라 프로토타입 완료 후 GitHub·Notion 게시 및 재확인까지 수행한다.

19:57:24 KST 최종 빌드에서 네트워크 파이프라인 7단계(방 관리 2/3/4인·과도 요청 격리·서버 챕터 시작/이동 2/3/4인)가 19:59:36 KST 통과했다. 일반 화면 11종은 20:00:18 KST 통과했으며 최종 로비·대기방 PNG와 네트워크 2/4인 챕터 PNG를 직접 확인했다. 문서 계약 788개와 검사기 자체 회귀 22개도 통과했다. 이 결과를 전체 코스 온라인 완주·클라우드·게시 완료로 확대하지 않는다.

새 구현에는 일반 5구간·협동 보스, 시작 인원 고정 장치, 구조 대기·전멸 복귀, 스태미나·앉기·벽 타기, 소지품·운반, 지역 시험 기믹, 한글 uGUI·로컬 품질/키 설정, 버전 포함 로컬 저장, 연결/방장 이전 시뮬레이션이 포함된다. 시험 수치·기믹 조합·콘티는 최종 승인으로 승격하지 않는다. PlayFab·Steam은 여전히 미연결이다.

## 2026-09-18 로컬 프로토타입 기준선 이력

당시 GitHub `main`은 기획·폴더 골격의 기준이었고, 이를 바탕으로 제작한 초기 Unity 구현을 `codex/00-prototype-baseline` 브랜치의 커밋 `660b423`으로 게시했다. 아래 목록은 당시 확인 기록이다. 최신 작업은 위 실제 구현 상태와 작업별 검증 문서를 따른다.

- `Assets/Game/Core/Prototype`, `Assets/Game/Features`, `Assets/Game/Editor`에 로비·대기실·Chapter01~07·스토리 인터루드 흐름을 생성하고 실행하는 C# 프로토타입 코드가 있습니다.
- 기존 작업 기록과 `Build/SlimeCoopPrototype.provenance.json`은 과거 Unity 6000.6.1f1 Windows 빌드 성공을 증명합니다.
- 2026-09-18 Unity 6000.6.1f1에서 `PrototypeSceneBuilder.BuildScenes`를 실행해 `PrototypeLobby.unity`, `PrototypeWaitingRoom.unity`, `PrototypeChapter01~07.unity`, `PrototypeStoryInterlude_Chapter01~07.unity` 총 16개 씬과 메타데이터를 재생성했습니다.
- `ProjectSettings/EditorBuildSettings.asset`은 로비·대기실·챕터와 스토리 인터루드를 흐름 순서대로 16개 등록합니다. 현재 소스의 별도 Windows 검증 빌드는 `Errors: 0`으로 성공했습니다.
- 프로토타입 흐름은 `Lobby → WaitingRoom → 선택한 Chapter01~07 → 해당 StoryInterlude → WaitingRoom`입니다. 챕터 출구 집계가 끝나면 컷신 placeholder로 자동 이동하고, 컷신에서 계속하기를 누르면 대기실로 돌아옵니다.
- `PrototypeSceneBuilder`는 오브젝트·카메라·조명·placeholder 재질/스프라이트와 16개 씬을 생성하고 Build Settings에 등록합니다. `PrototypeBuild`로 현재 소스의 Windows 검증 빌드를 재현했습니다.
- 캡슐·기본 색상·임시 2D 장식은 기능 확인용 placeholder입니다. 최종 캐릭터·몬스터·UI·VFX·SFX·조명·후처리 스타일은 사용자 승인 전까지 확정하지 않습니다.
- 이 구현은 서버 권한, Steam 인증·제재, PlayFab 운영, 실제 네트워크 동기화 또는 저사양 성능 목표를 충족했다는 의미가 아닙니다. 각 항목은 별도 검증 대상으로 유지합니다.

기존 구현 완료 기록과 빌드 산출물은 당시 결과의 증거로 보존하며, 현재 파일 상태의 새 검증은 [TASK-0004](Maintenance/TASK-0004-SourceBaselineIntegration.md)에 별도로 연결한다. 씬·메타데이터 재생성·컴파일·빌드·헤드리스 초기 기동은 확인했지만 화면 흐름 전체의 수동 회귀 결과로 확대 해석하지 않는다.

## 확정된 운영·사용자 결정

- 로비는 2D로 유지하고 슬라임 대기방은 직접 걸어 다니는 1인칭 3D 공간으로 만든다. 챕터 선택 지점에서 선택한 뒤 준비 장치에서 출발한다.
- 이야기 계속하기·건너뛰기는 현재 접속 중인 전원 동의로 함께 복귀한다. 접속 종료자는 이야기 투표에서만 제외하며 출구 점수의 시작 명단은 고정한다.
- 프론트엔드는 플레이어가 보고·듣고·느끼는 클라이언트 경험 계층으로 정의한다.
- 캐릭터·몬스터·보스 외형, UI/UX 스타일, VFX·SFX·음악·애니메이션·카메라·조명·후처리·지역 분위기의 최종 결정권은 사용자에게 있다. AI는 후보안과 기술 영향을 제안하며 사용자 승인 전에는 확정·구매·외주·제작 지시로 사용하지 않는다.
- 고품질 아트의 기본 방향은 포토리얼리즘이 아닌 판타지 이세계풍 스타일라이즈드이며, 저사양 PC 성능을 고려한 LOD·텍스처·셰이더·VFX·컬링을 우선한다.
- 자동·낮음·중간·높음·사용자 지정 품질 프리셋은 클라이언트 로컬 표현만 조절하며 서버 판정·충돌·점수·출구·협동 조건·랭킹을 변경하지 않는다.

## 확정 이후 적용 원칙

- 이전의 전원 입장 필수, 개인 협동 점수, 몬스터 처치 점수는 적용하지 않는다.
- PC 보호 제품 동봉과 전화번호 기반 통합 제재는 현재 범위에 포함하지 않는다. 서버 검증과 Steam 계정의 검토된 증거를 사용한다.
- 방장 역할은 이전하지만 게임 서버의 판정권은 이전하지 않는다.
- 도착 인원 보너스·4인 공개 랭킹·동점 시 시간 우선은 기존 구체 확정 규칙을 유지한다. 최신 메모에 후보로 다시 등장한 별도 전원 보너스는 채택하지 않는다.
- 빌드 버전 필드명은 기존 GitHub의 gameBuildVersion을 문서 표준으로 사용한다. 별도 migrationVersion은 변환 이력에 둔다.
- game-planning-choice·game-planning-kit·deliverables·tmp는 외부 메모의 작업 경로이며 이 저장소에 존재하는 관리 구조로 표시하지 않는다. 실제 구조는 [폴더 지도](FOLDER_MAP.md)를 따른다.
