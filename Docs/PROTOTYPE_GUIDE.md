# 통합 기획 프로토타입 — 실행과 확인

기준일: 2026-09-20 · 상태: 사용자 요청으로 추가 개발 중단, 현시점 프로토타입 인계. 전체 구현은 미완료다. [인계서](PROTOTYPE_HANDOFF.md)와 [게시 상태](PUBLISH_STATUS.md)를 함께 확인한다.

현재 작업 프로젝트는 이 저장소(`C:\Users\PC\Documents\ChatGPT\협동게임`)다. 예전에 사용한 바탕화면 템플릿과 혼동하지 않는다. 아래 구현 목록은 최종 게임 완성 선언이 아니다. 최신 실행 파일·전멸 재도전 검증은 [TEST-0011](Testing/TEST-0011-NetworkWipeRetry.md), 일반 로비의 실제 서버 생성·참가는 [TEST-0010](Testing/TEST-0010-LocalLobbyEntry.md), 서버 결과 저장·이야기 복귀는 [TEST-0009](Testing/TEST-0009-NetworkCompletion.md)에 구분한다.

## 실행

Unity 없이 실행할 때는 현재 로컬 Windows 빌드 `Build/FullPrototype/SlimeCoopPrototype.exe`를 연다. 다른 PC로 전달할 때는 EXE만 복사하지 말고 `FullPrototype` 폴더의 게임 데이터·런타임을 함께 전달한다. 로컬 대기방 기준선은 [TEST-0006](Testing/TEST-0006-WalkableWaitingRoom.md), 최신 검사 시각·범위·런타임 DLL 해시는 [TEST-0011](Testing/TEST-0011-NetworkWipeRetry.md)을 따른다. 16:02(KST)의 77개 검사·Full 파이프라인은 이전 기준선이다. 각 단계의 검증을 전체 챕터 멀티플레이 완료로 해석하지 않는다.

Unity 6000.6.1f1에서 `Assets/Game/Levels/Lobby/PrototypeLobby.unity`를 열고 Play를 누른다. 빈 Untitled 씬에서 시작하지 않는다. 로비의 **게임 시작**으로 3D 대기실에 들어간다. 씬을 재생성해야 할 때만 `Slime Prototype > Rebuild Prototype Scenes`를 사용한다. 이 명령은 프로토타입 생성 씬을 다시 작성한다.

슬라임 대기방은 직접 걸어 다니는 1인칭 3D 공간이다. 화면을 클릭한 뒤 WASD로 이동하고, 앞쪽 챕터 지점에 가까이 가서 바라보며 E를 눌러 선택한다. 중앙 준비 장치로 이동해 E를 누르면 선택한 챕터로 출발한다. 챕터를 고르기만 해서는 출발하지 않는다. 양옆 장치에서 2·3·4인 시험 인원·특기·전체 시험/해금·연습·기록·도입·2D 로비 복귀를 이용한다. Esc는 설정과 마우스 해제다. 키를 바꾼 경우 게임 안의 현재 키 안내를 따른다.

로비의 **게임 시작 · 시험 동료와 3D 대기방**에서는 한 명을 직접 조작하고 나머지는 로컬 시험 동료이며 동료 준비는 자동이다. **같은 PC 멀티플레이**에서는 실제 접속자가 각각 이동·준비한다. 일반 메뉴의 연결 검사는 [TEST-0010](Testing/TEST-0010-LocalLobbyEntry.md), 실제 대기방 이동/출발 기준선은 [TEST-0008](Testing/TEST-0008-NetworkWaitingRoom.md)에 기록한다. 게임 전체 온라인 완주와 구분한다.

`2D 로비 → 3D 대기실 → 선택 챕터의 일반 1~5구간 → 협동 보스 → 이야기 인터루드 → 대기실`

개별 다운은 구조 대기다. 실제 전원이 쓰러지면 임시 점수·진행을 초기화하고 2D 로비로 돌아간다. 영구 해금·업적·설정은 유지한다. 임의 런 초기화 단축키는 없다.

## 별도 로컬 서버·다중 클라이언트

명령어 없이 시작하려면 다음 순서를 따른다.

1. 첫 실행 창의 **같은 PC 멀티플레이 · 만들기 / 참가**를 누른다.
2. 이름·포트(기본 7797)·정원 2~4명을 지정하고 **방 만들기**를 누른다. 숨겨진 별도 서버가 시작되며 준비와 승인이 끝나면 3D 대기방에 들어간다.
3. 같은 EXE를 다시 실행한 다른 창에서 **서로 다른 이름**과 같은 포트를 입력하고 **참가**를 누른다. 한 창이 곧 한 실제 참가자다. 다른 PC나 인터넷 참가 기능은 아니다.
4. 참가 실패 시 안내를 확인하고 다시 시도하거나 취소한다. 같은 이름의 시험 저장은 두 창이 동시에 사용할 수 없다. 포트가 사용 중이면 다른 포트로 만들거나 기존 방에 참가한다.

진행·설정은 `기존 저장 루트/LocalPlayers/이름의 SHA-256`에 보관한다. 로비로 돌아와도 선택한 프로필은 유지되며 하단에 이름을 표시한다. 다음 실행에서 같은 이름을 입력하면 기록을 다시 사용한다. 이는 실제 인증 계정이 아니다. 미저장 진행이 있으면 저장을 재시도하기 전 다른 이름으로 바꿀 수 없다. 기존 일반 저장 파일은 이동·삭제하지 않는다. 아무도 참가하지 않은 생성 서버는 시작 후 30초에, 마지막 참가자가 나간 서버는 약 5초 후에 종료한다.

기존 개발 실행도 유지한다. 프로젝트 루트에서 `pwsh -NoProfile -File ./LocalNetwork.ps1 -Mode Play -Players 2`를 실행하면 숨겨진 전용 서버와 실제 클라이언트 두 창이 열린다. `-Players 3` 또는 `4`로 인원을 바꿀 수 있다. 첫 접속자가 방장이며, 각 창은 서로 다른 참가자다. 모두 접속 종료하면 서버도 종료한다.

각 창에서 화면을 클릭하고 WASD로 자기 슬라임을 움직인다. 방장이 앞쪽 챕터 장치 가까이에서 E로 선택한다. 각 참가자는 중앙 준비 장치로 걸어가서 바라보고 E를 눌러 준비창을 연 뒤 준비한다. 전원 준비 후 방장의 **선택한 챕터로 출발**로 명단을 고정하고 서버 챕터를 시작한다. 챕터를 변경하면 준비는 해제된다. 초기 시험 선택은 챕터 1이다. 멀리서 장치 사용을 요청하면 서버가 거부한다. Esc로 마우스를 풀면 오른쪽 아래 **로비로**에서 이 참가자만 연결을 종료할 수 있다. 방장 창을 종료하면 남은 참가자로 방장 역할이 이전하고 별도 서버와 시작 명단은 유지된다.

이 경로는 **개발 중인 실제 참가자 서버 실행**이다. 대기방도 1인칭 3D 공간이며 실제 접속자만 표시한다. [TEST-0008](Testing/TEST-0008-NetworkWaitingRoom.md)의 이동/장치 검사와 [TEST-0009](Testing/TEST-0009-NetworkCompletion.md)의 서버 시험 배치 정산/저장/복귀 검사를 구분한다. 일반 7챕터의 실제 입력 온라인 완주는 아직 검증하지 않았다. 시험 동료 AI와 T/Y 자동 배치는 없으며 참가자가 직접 협동한다. 로컬 인원 변경·특기/연습 장치를 멀티 기능으로 표시하지 않는다. 일부 지역 위험·아이템 사용 표현도 후속 연결 대상이다. 다른 PC 접속·Steam 인증/초대·PlayFab은 아직 사용할 수 없다. 서버는 `127.0.0.1`만 사용하며 방화벽이나 계정을 설정하지 않는다. 같은 최신 빌드끼리 실행하며 이전 로컬 통신 버전은 접속을 거부한다. 대기 중인 방에는 나갔다 다시 참가할 수 있지만, 모험 중인 런은 새 접속을 거부한다.

챕터 완료 결과와 발견한 기억은 각 참가자의 로컬 저장에 반영한다. 결과 화면에서 현재 접속한 전원이 계속하기에 동의하면 같은 서버의 3D 대기방으로 돌아간다. 동의는 철회할 수 있고, 접속 종료자는 투표에서만 제외한다. 일반 실행 스크립트의 저장 경로는 `Logs/Network/인원-player/Save-참가자이름`이며 Steam 계정 저장이 아니다. 서버가 완료할 때 이미 연결을 잃어 결과를 받지 못한 경우의 재전달은 아직 구현하지 않았다.

## 기본 조작

| 입력 | 동작 |
|---|---|
| 화면 클릭 / 마우스 | 시점 조작 시작 / 둘러보기 |
| WASD / Shift | 이동 / 앞·앞대각선 달리기 |
| Space / Ctrl | 점프 / 앉기 |
| 좌클릭 유지 | 표시된 벽에 붙어 이동. Space로 벽 점프 |
| E / E 유지 | 장치·아이템·상자 / 구조·큰 상자 밀기 |
| 1·2·3 / F / G | 소지 슬롯 선택 / 사용 / 든 상자 또는 선택 아이템 내려놓기 |
| T / Y | 로컬 동료를 각 협동 장치로 배치 / 따라오기. 바다의 지역 목표 진행 중에는 T로 부유물 탑승 |
| Q / N / J | 핑 / 목걸이 방향 안내·기억 발견 / 기록 다시 읽기 |
| Esc | 품질·음량·키·입력 방식 설정 |
| F2 | 로컬 이탈·재접속·동료 대기/앉기 시험 도구 |

키는 설정에서 바꿀 수 있다. 품질 적용 후 15초 안에 유지하지 않으면 이전 설정으로 복원한다. 낮은 품질도 필수 장치·위험 판정·동료·출구 규칙을 변경하지 않는다. 모션 블러는 없으며 현재 카메라 흔들림은 0이다.

메뉴·기록 창을 열어도 게임은 일시 정지하지 않는다. 마우스 조작을 풀어도 낙하와 적의 행동은 계속된다. 자동 품질은 장비에 맞춰 선택한 프리셋의 실제 렌더 비율을 표시하며, 렌더 비율을 직접 바꾸면 사용자 지정으로 전환한다.

## 구간 진행

1. 첫 방에서 이동·앉기·벽 타기를 연습하고 아이템을 찾는다.
2. 두 번째 방의 지역 장치를 작동한다. 용암은 발판 상태 변화, 오염은 정화, 산은 미끄러운 바닥의 시험 표현을 사용한다. 바다는 물속 잠금을 직접 풀고 T로 동료들을 부유물에 배치한다. 전원이 올라타고 조타 장치를 E로 사용하면 건너편으로 이동한다. 탑승자가 부족하면 운행이 멈추며 사망·이탈로 필요 인원을 줄이지 않는다.
3. 2구간부터 열쇠 연결, 일부 후반 일반 구간은 상자를 소켓으로 옮기는 조건이 추가된다. 소지 슬롯 수·구조 시간·배점·장치 순서는 시험값이다.
4. T로 동료를 배치하고 남은 장치에 직접 올라선다. 역할 수는 구간 시작 인원으로 고정한다.
5. 출구가 열리면 살아 있는 한 명의 진입으로 성공한다. 최대 5초 동안 추가 도착자를 집계한다. 전원 도착 시 조기 마감하며 실제 도착 인원이 보너스를 결정한다.
6. 구간 정산 뒤 다음 구간에서 미탈출자를 부활시킨다. 보스는 공동 장치를 세 번 가동한다. 노란 바닥은 3초 공격 예고, 붉은 바닥은 실제 피해 범위다. 가장자리로 대피했다가 안전 시간에 돌아온다. 시험 동료도 예고 때 대피한다.

아이템 후보 위치는 시드에 따라 달라진다. 필수 열쇠를 소지한 동료가 이탈해 회수할 수 없으면 첫 방의 원래 위치에 복구하고 이탈자의 중복 열쇠를 제거한다. 사망만으로 열쇠를 복제하거나 역할 수를 낮추지 않는다.

목걸이를 켜고 첫 방의 빛나는 기억에 다가가면 임시 기억 콘티를 발견한다. J 또는 대기실의 발견한 기억에서 다시 읽는다. 대기실의 로컬 팀 기록은 챕터·배점 버전·기록 시작 4인 조건으로 분리한다. 실제 공개 랭킹이 아니다.

개별 사망·이탈로 필수 역할을 줄이지 않는다. 구조가 불가능해 역할이 부족하면 접근 가능한 붉은 사망 경로를 통해 실제 전멸한 뒤 재도전한다. 지역별 구체 퍼즐과 보스 외형은 최종 승인된 콘텐츠가 아니다.

실제 참가자 연결에서는 전멸 후 **2D 전멸 결과 → 슬라임 대기방으로 → 중앙 준비 장치 → 같은 챕터의 1구간** 순서로 재도전한다. 서버와 접속을 유지하되 점수·시간·임시 진행과 준비 상태는 새로 시작한다. 해금·업적·이미 저장된 기억·팀 기록·설정은 유지한다. 검증 범위는 [TEST-0011](Testing/TEST-0011-NetworkWipeRetry.md)을 따른다.

## 저장·운영 경계

- 일반 로컬 저장: Unity의 `Application.persistentDataPath/PrototypeV2` 아래 `progress.json`, `settings.json`.
- 시험 중 자동 테스트는 별도 `Temp/PrototypeRules`, `Temp/PrototypeSceneTests`를 사용하며 사용자의 실제 진행을 덮어쓰지 않는다.
- 로컬 기록에는 시작 인원·빌드·배점 버전을 연결한다. 공개 Steam/PlayFab 랭킹에 제출하지 않는다.
- 저장 형식이 깨지거나 지원하지 않는 버전이면 원본을 보존하고 오류를 표시한다. 다중 슬롯·클라우드 장애 복구는 아직 없다.
- 일시적인 쓰기 실패는 화면에 **진행 미저장**으로 표시한다. 디스크 공간·쓰기 권한을 확인하고 설정 → 소리·접근성 → 미저장 진행 재시도를 사용한다. 종료 전 성공하지 못한 진행은 다음 실행에 남지 않는다. 손상/미래 버전 파일은 재시도로 덮어쓰지 않고 원본을 보호한다.
- 설정은 적용 후 유지 확인을 눌러야 영구 저장된다. 확인 중 값을 다시 바꾸면 새 미리보기가 필요하다. 15초 경과·취소·창 닫기는 이전 값을 복원하고, 쓰기 실패도 이전 값으로 돌아간 뒤 재시도를 허용한다. 설정 파일 오류가 진행 저장을 차단하지 않으며 반대도 같다.
- F2의 연결 변화는 로컬 시뮬레이션이다. 요청 검증 테스트가 실제 서버 보안을 입증하지 않는다. PC 검사·타 프로그램 삭제·실제 계정 제재 기능은 없다.

## 개발자 재검사

프로젝트 루트에서 `pwsh -NoProfile -File ./PrototypePipeline.ps1 -Mode Full`로 문서 검사 → 16개 씬 생성 → PlayMode → Windows 빌드 → 오프스크린 캡처 → 2/3/4인 별도 프로세스 방 관리·과도 요청 격리·서버 챕터 시작/이동 → 서버 시험 배치 정산·저장·동의·복귀 → 일반 로비의 2/4인 생성·참가·재참가를 실행한다. 편집기를 자동으로 종료하지 않으므로 작업을 저장하고 닫은 상태에서 실행한다. `Test`, `Build`, `Capture`, `Network`, `Lifecycle`, `Lobby` 모드로 단계별 실행도 가능하다. `Lifecycle`은 자동 배치가 명시된 전환 검사이며 일반 플레이가 아니다. Unity CLI와 이미 설치된 6000.6.1f1·활성 라이선스가 필요하다.

`-Mode Wipe`는 서버 시험 배치 후 실제 위험 지대 이동·전멸·2D/3D 복귀·새 런 재시작을 2/3/4인으로 검사한다. `Full`의 마지막 단계에도 포함한다. 명시적 시험 배치를 실제 코스 완주로 해석하지 않는다.

결과는 `Logs/PrototypePipelineReport.json`과 각 Unity 로그·XML, `Build/FullPrototype/Captures/result.json`에서 확인한다. 캡처 자동 통과 뒤에도 PNG 직접 검수가 필요하다. 파이프라인은 저장소를 게시하거나 비밀 키를 설정하지 않는다.

## 제작·검증이 더 필요한 범위

실제 PlayFab 전용 서버·Steam 인증/초대·전체 챕터 네트워크 동기화, 서버 지연/손실/장애, Game Ban 운영 연결은 미구현이다. 최종 시나리오·영상·캐릭터/보스 아트·SFX/VFX/음악은 미승인이다. 최소 사양 성능, 두 명의 초보자 이해도, 장시간 플레이는 아직 입증하지 않았다. 로컬 시제품은 위 영역의 완성을 대신하지 않는다.
