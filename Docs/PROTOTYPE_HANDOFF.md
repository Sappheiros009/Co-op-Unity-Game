# 프로토타입 인계서

기준일: 2026-09-20 · 상태: 사용자 요청으로 추가 개발 중단. 완성·출시 승인 아님.

## 인계 기준

현재까지 제작한 소스·씬·설정·기획·검증 기록을 게시한다. 개발 목표는 일시정지 상태로 유지하며 사용자의 재개 지시 없이 기능 구현을 이어가지 않는다. 확정 기획은 [Plan.md](../Plan.md), 원격 반영의 실제 결과는 [게시 상태](PUBLISH_STATUS.md)가 기준이다. 대화 질문·선택지를 확정 기획에 섞지 않는다.

## 구현 범위

- Unity 6000.6.1f1 프로젝트와 16개 씬: 2D 로비, 직접 걷는 1인칭 3D 대기방, Chapter01~07, 챕터별 이야기 인터루드.
- 정상 흐름: 2D 로비 → 3D 대기방의 챕터 선택 지점 → 중앙 준비 장치 → 일반 5구간·협동 보스 → 이야기 → 3D 대기방.
- 이동·등반·협동 장치·운반·구조·추적 몬스터·지역 위험·출구 집계·팀 정산·저장·설정의 기능성 프로토타입. 직접 공격 기능은 두지 않는다.
- 몸통·머리/얼굴·손·발·목걸이를 구분한 기본 도형 캐릭터와 임시 색상·음향. 최종 에셋과 연출 승인으로 간주하지 않는다.
- 시험 동료 모드와 같은 PC의 별도 로컬 서버 + 실제 2~4개 클라이언트 모드를 구분한다. 일반 로비에서 서버 만들기·참가·취소·재시도·나가기·재참가를 제공한다.
- 시작 명단을 고정한 출구 집계·팀 결과와 현재 접속자 전원 동의에 따른 이야기 복귀를 연결한다. 참가자 이탈로 출구 시작 명단을 줄이지 않는다.
- 실제 전멸 후 런 점수·시간·구간 등의 임시 정보를 초기화한다. 2D 결과/로비 → 3D 대기방 → 같은 챕터 첫 구간의 새 런으로 이어지며 영구 진행·설정은 유지한다.

## 실행 방법

1. Unity 6000.6.1f1에서 이 저장소를 연다.
2. `Assets/Game/Levels/Lobby/PrototypeLobby.unity`를 열고 Play를 누른다. 빈 Untitled 씬에서 시작하지 않는다.
3. 시험 동료 경로로 대기방에 들어가면 WASD·마우스로 이동하고, 챕터 지점 근처에서 E로 선택한 뒤 중앙 준비 장치를 이용한다.
4. 실제 다중 클라이언트는 같은 PC에서 현재 Windows 빌드를 여러 창으로 실행하고 일반 로비의 만들기/참가를 사용한다. 각 창에 서로 다른 이름을 지정한다. 실제 참가자는 각자 중앙 장치에서 준비한다.

현재 로컬 실행 파일은 `Build/FullPrototype/SlimeCoopPrototype.exe`다. 실행 파일·게임 데이터는 소스 저장소에 포함하지 않는다. 빌드 재현·상세 조작은 [실행 안내](PROTOTYPE_GUIDE.md)를 따른다.

## 남은 작업과 검증 한계

- 7개 챕터 전 구간의 연속 실제 입력 완주, 장시간 플레이, 초보자 사용성은 미검증이다. 자동 검사에는 서버 시험 배치·가속 절차가 포함된다.
- 일부 지역 위험·아이템 사용 표현, 이동 예측/보정, 모험 도중 안전 합류·재접속·결과 재전달은 후속 작업이다.
- 통신 검증은 같은 PC의 `127.0.0.1` 전용이다. 다른 PC·인터넷·지연/손실·Steam 인증/초대·PlayFab 운영자 전용 서버는 미연결 또는 미검증이다. 계정·유료 서비스·방화벽을 새로 구성하지 않았다.
- 최소 사양·실제 저사양 성능·전체 품질 프리셋 실측은 미검증이다.
- 최종 캐릭터·몬스터·보스·UI·Blender 에셋·컷신·SFX/VFX·음악·배점·세부 서사는 승인 또는 별도 제작이 필요하다. 기존 사용자 결정권을 유지한다.
- 실제 핵 탐지·운영자 증거 검토·Steam Game Ban 집행·출시는 미연결이다. 타 프로그램 강제 삭제는 구현·게시하지 않는다.

상세 요구별 차이는 [기획 충족도](PROTOTYPE_COVERAGE.md), 책임 폴더는 [폴더 지도](FOLDER_MAP.md), 재개 전 결정 사항은 [개발 상태](PROJECT_STATE.md)에서 찾는다.
