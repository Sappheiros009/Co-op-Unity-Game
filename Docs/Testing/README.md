# Testing — 검증 관리

[검증 양식](TEST_REPORT_TEMPLATE.md)에 환경·버전·실행 방법·기대 결과·실제 결과·증거·미검증 범위를 기록한다. 구현 전 기대 결과를 실제 통과로 표시하지 않는다.

## 공통 판정과 증거 규칙

- 표준 판정: `PASS`, `FAIL`, `BLOCKED`, `NOT_RUN`, `NOT_APPLICABLE`.
- `PASS`는 해당 조건·환경·커밋에서 실제 증거가 있는 경우만 사용한다.
- 문서·코드 존재·빌드 성공은 게임 동작·온라인·배포 성공으로 간주하지 않는다.
- 로그·JUnit·빌드 해시·실행 식별자는 결과와 같은 실행에서 생성된 자료만 연결한다.
- 외부 서비스·라이선스·실제 클라이언트가 없으면 `BLOCKED` 또는 `NOT_RUN`으로 남긴다.

테스트·버그·운영 기록의 공통 범위와 연결 규칙은 [TEST-0012](TEST-0012-TestBugOperationsBaseline.md)에서 관리한다. 문서 구조 검사는 다음 명령으로 별도 실행한다.

```powershell
pwsh -NoProfile -File ./Docs/Testing/Test-OperationalRecords.ps1
```

| 영역 | 핵심 검사 |
|---|---|
| Player·Cooperation | 벽 타기·끌어올리기·구조, 연속 동작, 장시간 플레이 |
| Puzzles·MapGeneration·Levels | 시작 인원별 역할, 진행 가능성, 고립 후 사망 경로 |
| StartandExit | 최초 도착·5초·조기 마감·실제 인원·단일 정산·전멸 |
| Online | 2·3·4인, 지연·손실·중복·끊김·방장 이전·서버 장애 |
| Save | 계정/런/경쟁 분리, 중복 결과, 변환 실패·정상 복구 |
| UI·Story·Localization | 사건 표시·스킵·대사·글자 누락·잘림·실제 이해 |
| 보안·운영 | 부정 요청 거부·오탐·제재 심사·이의제기·기록 복구 |

공개 협동 랭킹은 4인 출발 클리어 기록이며 일반 이탈·사망·일부 미탈출만으로 무효화하지 않는다. 팀 점수만 생성한다. 몬스터 점수·별도 전원 보너스·인원 비율 보정은 생성하지 않는다.

현재 실행 가능한 검사는 [기획 파이프라인](../PIPELINE.md), 검사기 자기 테스트, PlayMode 기능/씬 회귀, 별도 프로세스 로컬 네트워크 대기실 검사다. 초기 근거는 [TEST-0001](TEST-0001-PlanningPipeline.md)과 [TEST-0002](TEST-0002-PrototypeExitRules.md)에 있다. 게임 전체 수동 완주·전체 챕터 멀티플레이·클라우드 보안 운영은 아직 미검증이다.

2026-09-19 통합 기획 프로토타입 재제작의 새 회귀와 미검증 범위는 [TEST-0003](TEST-0003-FullPrototype.md)에서 관리한다.

로컬 전용 서버와 실제 2~4개 클라이언트의 통신 증거는 [TEST-0004](TEST-0004-LocalNetwork.md)에서 관리한다. 기존 시험 동료나 출구 모델 검사와 혼동하지 않는다.

서버용 참가자 입력·카메라 격리, 실제 플레이어 구조/끌어올리기, 입력 버퍼 검사는 [TEST-0005](TEST-0005-ServerPlayerControl.md)에서 관리한다. 실제 챕터 통신에 연결하기 전의 물리·입력 계약 검증이다.

직접 걷는 3D 대기방·근접 장치 선택·준비 출발·로비 2D 유지와 이야기 전원 동의 규칙은 [TEST-0006](TEST-0006-WalkableWaitingRoom.md)에서 관리한다. 일반 로컬 대기방과 별도 서버 대기실의 구현 범위를 구분한다.

서버 챕터 시작·연결별 입력 이동·표시 전용 복제의 실제 2/3/4인 검사는 [TEST-0007](TEST-0007-NetworkWorldReplica.md)에서 관리한다. 전체 코스·이야기·영구 저장의 다중 클라이언트 완료 검증은 아니다.

별도 서버의 직접 걷는 3D 대기방·근접 준비 장치·입력 세대 분리와 실제 참가자의 장치 접근 회귀는 [TEST-0008](TEST-0008-NetworkWaitingRoom.md)에서 관리한다.

서버 완료 결과·개인 로컬 저장·이야기 합의·3D 대기방 복귀는 [TEST-0009](TEST-0009-NetworkCompletion.md)에서 관리한다. 챕터 내 서버 시험 배치를 사용하는 전환 검사이며 다중 클라이언트의 코스 이동 완주와 구분한다.

일반 2D 로비의 숨김 전용 서버 생성·같은 PC 참가·취소/재시도·3D 대기방·이탈/재참가와 이름별 시험 저장 잠금은 [TEST-0010](TEST-0010-LocalLobbyEntry.md)에서 관리한다. 실제 버튼 콜백 시험과 사람의 네이티브 창 마우스 검수를 구분한다.

전멸 후 클라이언트 임시 상태 초기화·2D 결과·3D 대기방 복귀·새 런 재도전·영구 데이터 보존은 [TEST-0011](TEST-0011-NetworkWipeRetry.md)에서 관리한다. 서버 시험 배치와 실제 클라이언트 위험 지대 이동의 범위를 구분한다.
