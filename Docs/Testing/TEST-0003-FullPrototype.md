# TEST-0003 — 통합 기획 프로토타입 재제작 검증

기준일: 2026-09-19 · 상태: 로컬 회귀·빌드·렌더 통과, 전체 기획 충족도는 진행 중

## 환경과 증거 경계

현재 작업공간의 Unity 6000.6.1f1 Windows 프로젝트를 검증한다. 기존 TEST-0002의 4개 출구 테스트 통과는 이전 버전의 결과로 보존한다. 이번 변경의 성공으로 재사용하지 않는다.

## 최신 결과 요약

- PlayMode **77/77 통과**, 152.857초. 기존 제어된 참가자 배치의 42구간·저장·설정·구조 회귀 71개와 순수 네트워크 방 모델 6개다. 전체 수동 플레이 검사가 아니다.
- `PrototypePipeline.ps1 -Mode Full`: **통과**, 문서 검사 → 16개 씬 재생성 → PlayMode 77/77 → Windows 빌드 → 일반 화면 11종 → 실제 2/3/4인 별도 프로세스 대기실 → 과도 요청 격리를 한 번에 완료했다. `Logs/PrototypePipelineReport.json`의 상태 PASSED, 시작 15:55:53·종료 16:02:28(KST).
- Windows 빌드 `Errors: 0`, 16:00:41(KST) provenance 성공 확인. 변경 없는 런타임 DLL의 파일 시각이 이전 컴파일 시각인 15:54에 머무는 것은 빌드 캐시 재사용이다. 이후 대기실 4행 표시 보강 빌드·렌더는 [TEST-0004](TEST-0004-LocalNetwork.md)에 따로 기록한다.
- 16:01(KST) 생성된 PNG 11장을 모두 직접 열었다. 로비·대기실·광산·설정·LAVA·이야기·보스 예고·부유물·기억·팀 기록·저장 장애 안내에서 한글/핵심 표시를 확인했다. QA 종료 코드 0, `result.json` 오류 0. 저장 장애는 격리된 QA 파일을 실제로 잠가 만들었고, 잠금 해제 후 설정창 버튼으로 재시도 성공했다.
- 통합 Full 당시 문서 검사 **654/654 통과**, 실패 0. 문서 후속 편집의 최신 수치는 `LatestPipelineReport.json`을 기준으로 한다. 검사기 자체 테스트 **20/20**은 같은 날짜의 앞선 실행 결과이며 게임 검증과 구분한다.
- 자동 품질은 GT 1030에서 낮음·렌더 70%로 표시한다. 대기실 4개 파츠형 캐릭터는 양쪽 메뉴 사이에 보인다. 보스 예고 바닥과 기억 발견 내용도 실제 렌더에 나타난다.
- 사용하지 않는 DOF·Panini 후처리 셰이더 경고 4개는 남는다. 런타임 예외는 없으며, 최소 사양 FPS·실제 창의 전체 입력 완주·온라인 서비스는 미검증이다.

## 초기 실행 기록

### 저장·설정 안정성 확장

최초 저장 전에 파일을 읽지 않은 경로, 일시적 쓰기 실패 뒤 재시도, 잘못된 팀 기록 형식을 추가 검사했다. 수정 전 **3/3 실패**를 실제 재현했다(`Logs/persistence-before.xml`). 읽기 원본 보호와 쓰기 오류를 분리하고 진행/설정 오류를 독립 관리한 뒤, 저장·설정 집중 회귀 **13/13 통과**, 18.831초(`Logs/persistence-settings-after.xml`).

설정 UI 검사는 실제 uGUI 버튼 이벤트로 미리보기/유지/재편집/취소/외부 닫기, 실제 15.3초 대기 중 게임 시간 정지 상태의 자동 복원, 쓰기 실패 후 복원·재시도를 검사한다. 원본 보호·재시도 검사는 별도 GUID 임시 경로만 사용한다. 손상 원본의 초기화·자동 백업 정책은 추가하지 않았다.

구조 검사 초기 실패는 포커스가 없는 배치 편집기가 커서 잠금을 해제하고 시험 키보드를 편집기로 라우팅한 데서 발생했다. 설치된 Input System의 포커스 설정을 확인하고 시험 실행 중에만 입력을 게임으로 라우팅했다. 실제 게임의 커서/메뉴 제한은 유지한다. `PrototypeInteraction`의 입력 수집과 판정을 분리해, 실제 키 상태로 만든 스냅샷과 실제 충돌체를 검사한다. 배치 입력 소유권만 시험에서 주입하므로 실제 창의 키보드 완주로 주장하지 않는다.

확장 상호작용 회귀 **7/7 통과**, 17.748초(`Logs/interaction-after.xml`). E 유지 취소, 벽 차폐, 회복팩 소모와 보호 만료, 힐러 무자원 구조 시간, 메뉴/입력 소유권 상실, 끌어올릴 공간, 음수·비정상 회복값을 확인했다. 입력 설정은 검사 종료 시 복원한다.

15:22 이후 사용자가 로컬 전용 서버·다중 클라이언트 검증을 선택했다. 새 네트워크 코드는 후속 77/77 및 별도 프로세스 [TEST-0004](TEST-0004-LocalNetwork.md)로 검증했으며, 그 이전 싱글 프로세스 71/71 결과와 구분한다.

- 소스·씬 생성기·테스트를 확장했다. 아직 전체 결과를 통과로 표시하지 않는다.
- 첫 샌드박스 실행은 라이선스 IPC 접근 문제로 중단하고, 해당 작업의 검증 인스턴스만 정리했다.
- 일반 실행 권한의 첫 컴파일에서 Video 모듈 누락을 발견했다. Package Manager API로 `com.unity.modules.video@1.0.0`을 추가했고 manifest 반영과 설치 완료 로그를 확인했다.
- 새 소스 컴파일과 16개 씬 재생성이 Unity CLI `run` 종료 코드 0으로 완료됐다. 로그: `Logs/full-prototype-buildscenes.log`, `[PrototypeSceneBuilder] Built Lobby` 완료 문구 확인.
- 첫 PlayMode 결과: 24개 중 17 통과 / 7 실패. 6개 씬 검사는 TMP 기본 리소스 누락으로 시작 단계에서 실패했고, 1개 저장 검사는 미래 버전의 InvalidDataException 처리가 누락됐다. 테스트를 완화하지 않고 가져오기 완료 대기와 예외 처리를 수정한다.
- Windows 플레이어·시각 결과는 후속 실행 결과로 이 문서를 갱신한다.

## Windows·렌더 검증 진행

- 1차 Windows 빌드 성공: `[PrototypeBuild] Result: Succeeded; Errors: 0`. 실행 파일 `Build/FullPrototype/SlimeCoopPrototype.exe`, provenance와 로그로 확인했다.
- 해당 플레이어의 숨김 QA 실행은 종료 코드 0, 런타임 예외 0이었으나, 직접 연 PNG 6장은 모두 검은 화면이었다. 이를 시각 검증 성공으로 인정하지 않는다. 배치 모드의 자동 화면 캡처 대신 실제 카메라를 RenderTexture로 명시적으로 렌더하고 균일색 검사·직접 이미지 검수를 추가한다.
- 장비에서 확인한 GPU는 NVIDIA GeForce GT 1030이다. 이 정보만으로 최소 사양 성능 충족을 주장하지 않는다.
- 코드 검토에서 벽 타기 좌우 방향과 점프 직후 재부착을 보완했고, 2/3/4인·달리기 방향 회귀를 추가했다. 24개 통과 기록 이후 소스가 변경되어 재검사 중이다.
- 확장 회귀: **PlayMode 32/32 통과**, 실패 0, 38.550초. 수정된 소스의 Windows 빌드와 오프스크린 캡처를 다시 검증한다.
- 이어진 Windows 재빌드 성공(`Errors: 0`). 명시적 URP RenderTexture로 다시 촬영한 로비·3D 대기실·광산·설정·LAVA·이야기 PNG 6장을 직접 열어 한글 표시와 실제 장면을 확인했다. `Build/FullPrototype/Captures/result.json`의 오류 목록은 비어 있고 QA 플레이어는 종료 코드 0이다. 사용하지 않는 후처리 셰이더의 제거 경고 4개는 남아 있다.
- 이 캡처는 오버레이 Canvas를 촬영 중에만 카메라 Canvas로 옮긴 오프스크린 증거다. 실제 창의 마우스 조작·FPS·전체 완주 검증을 대신하지 않는다. 검사 중 확인한 대기실 가림, 인원 변경 순서, 자동 품질 표시, 메뉴 중 낙하 정지 문제를 후속 수정하고 이동 물리 회귀를 추가했다.

## 회귀 범위

후속 물리 확장 검사 1차는 10/11 통과였다. 점프 유예 만료 검사는 모터를 끈 채 시간을 기다려 CharacterController의 이전 접지 결과를 유지하는 시험 드라이버 문제를 발견했다. 실제 플레이처럼 낙하 중에도 매 프레임 모터를 진행하도록 고쳤다. 모서리 연결, 착지 전 점프 버퍼, 반대 방향 밀기 상쇄·같은 참가자 중복 힘 차단, 떨어진 열쇠의 지정 위치 복구 검사는 1차부터 통과했다. 현재 수정본의 통합 Full 파이프라인을 실행한다.

수정 후 통합 실행의 **PlayMode 51/51 통과**, 117.674초. 큰 상자 밀기는 참가자별 방향 요청을 물리 틱에서 한 번 합산하므로 렌더 프레임의 중복 호출로 힘이 늘어나지 않는다. 피로 유예에는 추가 등반 이동을 허용하지 않고, 떨어뜨린 필수 열쇠는 위험한 낙하 지점이 아닌 원래 지정 위치로 돌아간다.

2026-09-19 후속 이동·UI 회귀 **39/39 통과**, 41.363초. 실제 CharacterController로 달리기·천장 앉기 유지·벽 이동·벽 점프·꼭대기 전환을 검사하고, 입력 시스템의 가상 키보드 상태와 메뉴 중 중력을 확인했다. 물리 검사에서 모터 입력을 직접 공급한 경우는 실제 키보드 완주와 구분한다.

이후 42구간 연속 정산·저장·스토리 복귀, 협동 부유물, 열쇠 복구, 방향 안내·순위 분리 검사를 확장했다. 이 추가 변경의 결과는 후속 실행으로 확정한다.

확장 1차는 **44/45 통과**였다. 바다 2구간에서 몬스터 충돌로 동료가 부유물 범위를 벗어나 탑승 인원이 부족해졌다. 상세 위치·체력 덤프로 재현했으며, 검사에서 동료를 제자리 대기에 고정한 것이 원인이었다. 실제 T 탑승 명령의 `RegionAssist`를 사용하도록 수정한 뒤 몬스터가 있는 4인 부유물 회귀 1/1이 통과했다. 충돌·몬스터·탑승 인원 조건을 제거하지 않았다.

최신 전체 결과: **PlayMode 46/46 통과**, 실패 0, 116.821초. 일곱 챕터의 각 일반 5구간·보스(총 42구간)를 실제 장치/출구/타이머·씬 전환으로 연속 검사했고, 7개 팀 결과 저장·해금·스토리 복귀를 확인했다. 참가자를 제어된 위치에 배치한 가속 통합 검사이며 실제 키보드로 42구간을 완주한 기록이 아니다. 최신 소스의 새 Windows 빌드·10개 렌더 캡처를 진행한다.

`PrototypeExitScoringTests`: 첫 도착·중복·다운·전원 조기 마감·5초 집계.

`PrototypeRulesTests`: 출구 개방/거리/명단/마감 경계, 진입자 안전, 소지 제한·원자적 전달, 소유권·재전송·좌표 요청 거부, 방장 역할 이전, 증거 없는 제재 금지, 전멸/영구 저장 분리, 중복 저장, 손상·미래 저장 원본 보존, 시드 재현, 키 충돌.

`PrototypeSceneFlowTests`: 실제 로비 버튼→대기실, 단일 EventSystem·한글 글리프, 7개 챕터 구조·파츠·품질 판정 불변, 동료의 물리 이동, 장치→출구→정산→다음 구간 부활, 실제 전멸→로비, 7개 인터루드→대기실.

테스트가 직접 배치한 출구·장치 상태와 실제 입력을 통한 완주는 다른 증거다. 테스트 목록만으로 통과 또는 전체 수동 플레이 완료로 표시하지 않는다. 모든 42개 구간의 실제 조작 완주·저사양 성능·온라인은 별도 검증 대상이다.
